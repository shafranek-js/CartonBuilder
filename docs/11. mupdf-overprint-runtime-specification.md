Status: Implemented (custom renderer, process/spot plates, single/tiled parity); Adobe reference matrix remains a release gate
Owner: maintainer `src/artwork`, `src/pdf-renderer`
Last verified: 2026-08-08
Canonical for: рендер PDF/AI artwork через MuPDF.js, замена pdf.js-пути

## Контекст

ТЗ «Техническое задание по внедрению MuPDF.js для PDF-AI Overprint Preview»
(+ решение spike, `10. mupdf-capability-spike.md`): PDF/AI artwork рендерится
через `mupdf@1.28.0` (pinned), pdf.js-путь и CSS-multiply overprint удалены.
Overprint simulation uses the tracked custom MuPDF 1.28.0 WASM build. A stock
MuPDF fallback is explicitly reported as unavailable and never claims that the
toggle is active.

## Поток загрузки PDF/AI

1. `fileValidation.validateArtworkFile` — `.ai`/postscript без PDF-магии
   маршрутизируется в PDF-путь (extension `ai`), не-PDF `.ai` позже
   отклоняется с `aiNotPdfCompatible`.
2. `fileLoader.loadArtworkFile` для `application/pdf` → `pdfArtworkLoader.loadPdfArtwork`
   (main thread, минуя fileWorker): openDocument → choosePage (если >1) →
   getPageInfo (boxes/rotation) → getLayers (OCG) → renderPage → PNG preview.
3. `fileLoader.renderPdfWithLayers` (пере-рендер по слоям/странице/page box/dpi) →
   `pdfArtworkLoader.renderPdfArtwork`.
4. Растр/видео остаются на прежнем `fileWorker`/`processArtworkFile`.

## Семантика рендера

- `toPixmap(matrix, DeviceRGB, alpha=false, showExtras=true, usage="Print", box)`.
- **Поворот страницы**: рендер выполняется БЕЗ применения `/Rotate`
  (`Matrix.concat(scale, Matrix.rotate(-rotation))`), а `pdfPageRotation`
  передаётся модели (как в pdf.js-поведении) — без двойного поворота.
- **Page box** (`pageBox` в source, default `CropBox`): MediaBox/CropBox/
  BleedBox/TrimBox/ArtBox; выбор в секции «PDF layers» (селектор `#pageBoxSelect`);
  переключение пере-рендерит превью.
- **Слои (OCG)**: `countLayers/getLayerName/isLayerVisible/setLayerVisible`
  (порядок слоёв — как отдаёт mupdf), превью пере-рендерится при toggle.
- **Масштаб превью**: капы 4096 edge / 16 Мп (`getPreviewScale`); для
  растеризации — dpi × targetWidthMm.
- **Пароль**: `pdfPasswordProtected`. **Повреждённые файлы**: `pdfDamaged`.
- **Worker**: создаётся лениво, ready-handshake (`{type:'ready'}`) исключает
  потерю сообщений во время top-level await инициализации mupdf; ошибка worker →
  `rendererUnavailable`; воркер пересоздаётся при следующем запросе.
- **Overprint**: mode `0` is knockout, mode `1` is composite overprint preview,
  mode `2` is separations/plate preview. The custom path renders into CMYK with
  `fz_separations` and converts to RGB only after applying `processMask`.
  `processMask` uses C=1, M=2, Y=4, K=8 and defaults to 15.

## Production rendering (Phase 2)

- **Отмена рендеров**: worker поддерживает команду `cancel` (`activeRenders` map);
  отменённый рендер не отправляет ответ и уничтожает pixmap. Клиент трекает
  «сессию» рендера (`session`): при новом рендере той же сессии старый
  отменяется и его pending-промис оседает с `AbortError` (вызывающий код
  игнорирует stale-результаты по генерации). Сессия = `source.id` artwork.
- **Слои/page box/растеризация** используют сессии — быстрые переключения
  отменяют устаревшие рендеры.
- **Пароль**: `open` возвращает `{ needsPassword }` (документ остаётся в
  registry); клиент вызывает `authenticate(docId, password)` → `{ ok, pageCount }`.
  Промпт — диалог `#passwordDialog` (ArtworkApp `promptPdfPassword`); пароль
  кэшируется по sha256 файла (`passwordCache`), повторные рендеры не спрашивают.
  Ошибки: `pdfPasswordCancelled`, `pdfInvalidPassword`, `pdfPasswordProtected`.
- **Disclaimer**: в View menu под read-only статусом overprint добавлена строка
  «Monitor preview is not a contract color proof» (`overprintProofNote`).
- **Memory regression**: `tests/unit/mupdfMemory.test.js` — 60 циклов
  open→render→close в Node с bounded-growth ассерциями (heapUsed/arrayBuffers).
- **Клиент** покрыт unit-тестами на mock-worker (`tests/unit/mupdfClient.test.js`):
  ready-handshake, round-trip, dedupe, кэш, session-cancel, ошибки.
  Парольный поток загрузчика — `tests/unit/pdfArtworkPassword.test.js`.

## Большие artwork и безопасность (Phase 3)

- **Tiled rendering**: при размере рендера > `RENDER_TILE_EDGE` (2048 px) каждый
  тайл создаётся тем же native MuPDF API, что и single render: ограниченный
  `fz_pixmap` с `fz_separations`, page box, matrix и usage `Print`. JS
  `DrawDevice` не используется для overprint; spot behaviors и process mask
  одинаковы в single/tiled путях. Overscan 1 px (ТЗ §16.2).
- **Лимит пикселей**: `RENDER_MAX_PIXELS` (32 Мп) → `pdfRenderTooLarge` (ТЗ §16.1).
- **Watchdog**: клиент отслеживает время ожидания запросов (`timeoutMs`, по
  умолчанию 60 с); при зависании — terminate worker, pending → `pdfRenderTimeout`,
  следующий запрос создаёт свежий worker (recovery).
- **Лимиты безопасности (ТЗ §19)**: файл ≤ 100 МБ (валидация), страницы
  ≤ 5000 → `pdfTooManyPages`, pixel-лимиты, parsing только в Worker,
  `disableJS()` при открытии (document JavaScript не выполняется).
- **Тесты**: `mupdfTiling.test.js` (тайлы = single render пиксель-в-пиксель для
  rot 0/90 и большой страницы 4000×2000), watchdog-тест в `mupdfClient.test.js`.

## Custom WASM wrapper и Overprint Preview (Phase 4)

- **Сборка**: `scratch/mupdf-src` (MuPDF tag 1.28.0,
  commit `205b8cf43551279d1215e88fe2845c5d595bade9` + submodules) + Emscripten
  4.0.8; reproducible POSIX script `scripts/build-mupdf-wasm.sh` и patch
  series `patches/mupdf/0001-overprint-core-and-wasm-api.patch`. Sources/build
  objects are ignored; the script uses a build suffix and never mutates the
  global `.emscripten`. Added glue in
  `platform/wasm/lib/mupdf.c`: `wasm_pdf_new_pixmap_from_page_with_usage_and_overprint`
  (режимы 0/1/2, зеркалит mudraw `-M`: реальные сепарации → composite/spot
  поведения; иначе пустой `fz_new_separations(0)` при overprint на странице),
  `wasm_pdf_new_pixmap_from_page_with_usage_and_overprint_tile`,
  `wasm_convert_pixmap_to_rgb_with_process_mask`, `wasm_convert_pixmap_to_rgb`.
  TS-glue: `PDFPage.toPixmapWithOverprint(...)`, `Pixmap.toRgb()`,
  `convertCmykToRgb(...)`.
- **Артефакты** в `src/pdf-renderer/custom/` (mupdf.js, mupdf-wasm.js,
  mupdf-wasm.wasm ~10.4 МБ) — Vite бандлит их в worker.
- **Worker**: `initRenderer()` — сначала динамический import custom-модуля,
  fallback на stock `mupdf`; `RENDERER_VERSION` = `mupdf-custom`/`mupdf`;
  `handleRender` принимает `overprintMode` (0/1/2). Overprint-рендер идёт в
  DeviceCMYK (субтрактивный destination обязателен для overprint) с
  конверсией CMYK→RGB после маски (single и tiled — native
  `toRgbWithProcessMask`).
- **Overprint в mupdf работает только в субтрактивном (CMYK) destination**
  (`resolve_color`); для process-красок OPM 0 = replace (semantic mupdf —
  white overprint OPM 0 видим, как в mutool -M 1); OPM 1 и spot/DeviceN
  дают ожидаемое сохранение фона. Расхождение с Illustrator (OPM 0 process)
  задокументировано как поведение ядра mupdf.
- **UI**: View menu — реальный тогл «Overprint Preview» (когда рендерер
  `mupdf-custom`); глобальная настройка `carton-builder-overprint`;
  `ArtworkApp.setOverprintEnabled` пере-рендерит все PDF с `overprintMode`
  из `getOverprintMode()`. Растеризация/пере-рендеры (слои, page box)
  используют `getOverprintMode()`.
- **Диагностика**: `getRendererVersion()` (клиент кэширует из `open`),
  `isOverprintAvailable()`.

## Панель сепараций (Phase 5)

- **Glue (custom WASM)**: `wasm_pdf_page_separations_count`, `wasm_pdf_page_separation_names`
  (NUL-разделённые), `wasm_pdf_page_separation_coverage` (рендер в DeviceCMYK,
  coverage process C/M/Y/K + spot-плашек), `wasm_pdf_new_pixmap_from_page_with_usage_and_overprint_behaviors`
  (по-плашечные поведения: composite=0, spot=1, disabled=2).
- **TS**: `PDFPage.separationCount()`, `separationNames()`, `separationCoverage(mode)`,
  `toPixmapWithOverprintAndBehaviors(...)`.
- **Worker**: команда `separations` возвращает отдельные `process` C/M/Y/K и
  `spots[{index,name,coverage}]`; рендер принимает `processMask` и
  `spotBehaviors` (legacy alias `separationBehaviors`; MuPDF: composite=0,
  spot=1, disabled=2). Оба параметра записываются в render diagnostics.
- **UI**: View menu → «Separations…» → `#separationsDialog`: все C/M/Y/K и
  spot-плашки переключаемы; любое изменение немедленно запускает mode 2 и
  сохраняется в проекте.
- **State**: `pdfSeparationVisibility` сохраняется как
  `{ process: [true,true,true,true], spots: { "0": true } }`. Старый flat
  object мигрирует; отсутствие состояния означает, что все плашки включены.
  Project schema v12 carries this migration because schema v11 is already used
  by the existing render/finish migration.
- **E2E/native**: `tests/e2e/overprint.spec.js` samples decoded canvas pixels;
  `scripts/test-mupdf-overprint.mjs` checks PDF and PDF-compatible AI probes,
  masks, OPM and single/tiled parity.

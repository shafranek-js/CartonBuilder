# UI-срез: шаг `0. Select Workflow`

## Результат

- Добавить перед `1. Create Box` самостоятельный полноэкранный шаг `0. Select Workflow`.
- Удалить блок выбора workflow из `Create Box`, освободив высоту для редактора развёртки.
- Новый пустой проект открывать на шаге 0 без предвыбранной карточки.
- Клик по `Quick Layout` или `Technical Dieline` сразу фиксирует выбор и открывает соответствующий `1. Create Box`.
- Реализовывать этот срез только после завершения и приёмки текущего Stage 4B: обе задачи изменяют `index.html`, `main.js`, стили, локализацию и E2E-тесты.

## UX и состояния

- Экран шага 0 содержит заголовок, краткое объяснение и две крупные карточки-кнопки в центре рабочей области. Сохранить текущие описания и обязательное предупреждение Technical `Reference-only · not production certified`.
- Карточки реализовать нативными `<button>`, а не скрытыми radio inputs: один клик является завершённым действием. Добавить `aria-pressed` только для уже активного workflow, видимый focus и управление Enter/Space.
- В новом пустом проекте обе карточки нейтральны. До выбора:
  - шаги 1–4 заблокированы;
  - autosave и Save/Place Artwork/export/preset-команды не создают фиктивный Quick-проект;
  - File → Open/New, Contacts, Settings и язык остаются доступны;
  - Packaging Box Designer не загружается.
- После выбора шаг 0 помечается завершённым, шаг 1 становится активным. Quick открывает существующий Quick editor; Technical лениво запускает PBD host.
- Шаг 0 всегда доступен из stepper:
  - текущая карточка отмечается как `Current`;
  - клик по текущему workflow просто возвращает в Create Box;
  - клик по другому workflow использует существующие confirmation, checkpoint и очистку зависимого artwork/Preview/Render;
  - Cancel или ошибка checkpoint оставляют пользователя на шаге 0, сохраняют исходный workflow и ничего не очищают.
- Autosave, импортированный архив, checkpoint restore и first-run example являются уже существующими проектами: они устанавливают workflow из `cartonSource/workflowSelection` и сразу восстанавливают сохранённый допустимый шаг, не показывая шаг 0.
- File → New очищает проект и после reload открывает шаг 0 без предвыбора, независимо от legacy localStorage workflow key.
- Stepper содержит пять пунктов `0–4`. На широком экране сохраняются подписи; до ширины, где центральная группа пересекается с меню, stepper переходит в компактный режим с номерами и accessible labels. Проверить минимум 1920, 1280, 900, 620 и 320 px.

## Реализация и интерфейсы

- Перенести существующий workflow picker из `boxStep` в новый `workflowStep`; `boxStep` должен содержать только Quick либо Technical editor.
- Расширить UI state machine значением `currentStep = 'workflow'` и порядком:
  `workflow → box → artwork → preview → render`.
- Добавить отдельный флаг `workflowChosen`. Внутренний Quick model может создаваться при bootstrap, но не считается пользовательским выбором и не должен сохраняться до клика.
- `transitionToStep('workflow')` и `window.cartonBuilderApp.showStep('workflow')` должны поддерживаться; `window.cartonBuilderApp.step` может возвращать `'workflow'`. До выбора `getState()` возвращает `null`, чтобы не выдавать внутренний Quick model за проект.
- `canPersistProject()` должен быть `false` до выбора и `true` после выбора либо успешного восстановления проекта.
- `workflowStep: 'workflow'` в project schema не добавлять. Шаг 0 — transient creation state; schema остаётся v17, archive v5, миграции не требуются. После выбора первое сохраняемое состояние имеет `workflowStep: 'box'`.
- Удалить применение сохранённого browser-default workflow к новому проекту. Сохранённый проект остаётся единственным авторитетным источником режима при restore.
- Сохранить существующие capability gates: Technical Preview/Render остаются недоступны. Не изменять PBD/vendor packages, геометрию, export или Stage 4B coordinate logic.
- Добавить английские и русские строки для `Select Workflow`, заголовка, пояснения, статуса `Current` и подсказок заблокированных команд.

## Проверка

- Unit-тесты state machine: пустой bootstrap, Quick/Technical selection, повторный выбор текущего режима, Cancel/error/success при смене режима, отсутствие persistence до выбора.
- Project-тесты: schema v17 не принимает и не сохраняет `workflow`; Quick/Technical autosave, archive и checkpoint восстанавливаются на прежнем шаге.
- Playwright:
  - новый проект показывает только шаг 0 без selection;
  - каждый тип карточки одним кликом открывает правильный Step 1;
  - PBD не стартует до Technical selection;
  - возврат на шаг 0 и смена workflow до/после artwork соблюдают confirmation/checkpoint policy;
  - Cancel полностью сохраняет живое состояние;
  - New Project возвращает на нейтральный шаг 0;
  - Quick и Technical autosave/archive bypass шага 0;
  - клавиатура, focus, ARIA и отсутствие пересечений stepper на контрольных ширинах.
- Обновить существующие E2E helpers: каждый тест нового проекта должен явно выбирать Quick или Technical перед Create Box.
- После реализации выполнить focused tests, полный unit suite, workflow E2E, `plugins:verify`, build, `graphify update .`, `git diff --check` и проверить dirty worktree. Не делать commit/push без отдельного указания.
- Следующий шаг: после приёмки Stage 4B передать этот план разработчику как отдельный UI-коммит.

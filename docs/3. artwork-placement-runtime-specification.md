# CartonBuilder Artwork Placement and 3D Preview — runtime specification

Status: implemented runtime contract
Version: 1
Date: 2026-07-30

This document records the implemented behavior of the modular Vite application.
It resolves the product decisions in the concept, questionnaire, and technical
research documents. This runtime specification takes precedence for the
implemented 2D and 3D release.

## 1. Scope and workflow

The application has four reachable steps:

1. **Create Box** builds a six-face rectangular-box net.
2. **Place Artwork** loads and transforms one artwork asset over the complete
   net.
3. **Preview / Export** provides a clipped 2D proof, a derived folded 3D view,
   and deliverables.
4. **Render** provides a separate closed-carton presentation scene and
   reproducible PNG/JPG still export.

The primary user is an artwork coordinator. The supported environment is
desktop Chrome at roughly 1024×720 or larger. Touch-specific interaction is
outside this release. WebGL 2 is required only for 3D; 2D and export remain
available when it is absent.

## 2. Compatibility

`BoxNetModel.toJSON()` retains the original shape. Face names, geometry colors,
defaults, dimension limits, SVG filename format, `window.BoxNet`,
`window.boxNetApp`, `box-net-complete`, and `box-net-cancelled` remain
compatible.

`window.boxNetApp` retains `model`, `render`, `addPanel`, `deletePanel`, `reset`,
and `getState`. `loadState` and `exportSvg` are additive.

`window.cartonBuilderApp` is additive and exposes the current workflow step,
combined project snapshot, step navigation, and artwork controller for host
integration and automated testing.

`window.cartonBuilderApp.preview3d` is an additive lazy facade with activation,
fold progress, camera projection, scene preset, panel selection, reset/render,
state, resource diagnostics, and disposal methods. Its state is transient and
does not alter `getState()` or the project schema.

## 3. Canonical coordinates and transforms

- All domain geometry is stored in millimetres.
- The global origin is the top-left corner of Front Panel.
- X increases rightward and Y downward.
- One `ArtworkModel` is the only source of centre, scale, quarter-turn rotation,
  and opacity.
- Aspect ratio is always locked.
- Valid scale is 1% through 2000%.
- Rotation is limited to 0°, 90°, 180°, and 270°.
- Initial placement is Fit + Center over the entire dieline bounding box.
- Embedded raster DPI is ignored for initial sizing; effective DPI is derived
  from source pixels and the actual physical placement.
- Effective DPI is derived from source pixels divided by displayed physical
  size.

The viewport is independent from artwork state. It automatically fits after an
asset loads, after a quarter-turn rotation, and after placement is explicitly
reset for new box dimensions. Move, scale, ordinary step changes, and returning
from Preview preserve viewport state.

## 4. Input

The editor accepts exactly one:

- PNG;
- JPG/JPEG;
- PDF page.

The maximum original asset size is 100 MiB. File content signatures are checked
against the declared MIME type. Empty, spoofed, unsupported, password-protected,
and unreadable files are rejected.

When a PDF has multiple pages, a modal page picker is required. The PDF preview
uses its `MediaBox`, includes the effective CropBox content at the correct
offset, and applies inherited `/Rotate` exactly once. The preview is rasterized
for interaction, while the original page is kept for vector-preserving PDF
export.

Loading a new asset after one already exists is only possible through
`Replace`, followed by system confirmation. Drag/drop is ignored after load.
A multi-file drop is rejected. Processing is cancellable; cancelling terminates
an active PDF loading/render task and ignores stale completion.

All processing is local. No artwork, project, analytics, or diagnostics data is
sent to a server.

## 5. Edit behavior

The initial artwork is selected. Supported interactions:

- pointer drag: move;
- corner drag: proportional scale with opposite corner fixed;
- `Alt` + corner drag: proportional scale about centre;
- wheel: viewport zoom around pointer;
- `Ctrl` + wheel: artwork scale;
- middle drag or `Space` + primary drag: viewport pan;
- arrows: 0.1 mm nudge;
- `Shift` + arrows: 1 mm nudge;
- `Ctrl`/`Cmd` + arrows: 10 mm nudge;
- `Ctrl`/`Cmd+Z`: undo;
- `Ctrl`/`Cmd+Shift+Z` or `Ctrl`/`Cmd+Y`: redo;
- `0`: fit viewport;
- `Escape`: clear selection;
- `Delete`: confirmed removal when Artwork is unlocked.

Numeric Center X/Y, Width, Height, Scale, and Opacity controls update the same
canonical transform. Reset Transform restores initial scale, zero user rotation
relative to the asset's intrinsic PDF rotation, full opacity, and dieline
centering. Remove is a separate confirmed action.

### Transform panel layout

The right sidebar uses one shared visual grid for position, size, and scale:

- the reference-point selector occupies the first column beside the `X/Y` and
  `W/H` rows;
- `X:` and `Y:` are the position labels, while `W:` and `H:` are the visible
  size labels;
- numeric inputs have the same height, width, padding, background, focus state,
  and right-aligned number formatting;
- `mm` and `%` occupy fixed unit columns, so their position does not depend on
  the number of digits in an input;
- `Scale` is shown once, with `X:` and `Y:` values aligned to the position and
  size input columns;
- the proportions chain is compact, sits directly beside `W/H`, and is centered
  between those two rows. When active it applies to pointer and numeric resize;
  when inactive, width and height can be changed independently.

History contains completed transform and settings commands, not pointermove
intermediates. Its limit is 100 entries. Replaced/removed asset bytes are not
stored in history.

### Image Crop

Crop is a non-destructive rectangle stored in artwork-local millimetres. `Crop`
opens a frame with move and corner handles; `Draw` opens a crosshair drag mode.
The active button changes to `Apply`, and the same action can be committed with
`Enter`. `Escape` cancels the transient preview, while `Clear` removes the
stored crop. Switching between the two crop modes applies the current preview
before opening the next mode. The frame, drawing overlay, SVG clip mask, and
all exports use the same artwork origin and quarter-turn rotation transform.
Completed crop and clear operations are included in Undo/Redo and autosave.
After Apply, the crop rectangle is the artwork's visible transform geometry:
selection, Width/Height, X/Y reference points, snapping, Fit/Fill, rotation and
reset use its bounds. The applied size is rebased to Scale X/Y 100% without a
visual change, and the crop scales together with the source afterward. Apply
and Clear leave the artwork selected. Clear removes only the mask; it preserves
all transforms performed after cropping and reveals the original around the
previously visible content. Crop and ordinary resize handles remain a constant
five screen pixels at every viewport zoom.

Project schema version 6 keeps the existing `{ x, y, width, height }` crop
shape and stores per-artwork quality preferences. Its v4 migration rebases
cropped current and Undo/Redo artwork states to the same visual-equivalent 100%
baseline; archive layout and original assets do not change.

## 6. Quality-adaptive artwork rendering

Each artwork stores independent `quality.preview` and `quality.render` values.
Preview quality allows `auto`, `150`, `300`, and `600` DPI and is used by Place
Artwork, Preview/Export, and the 3D inspection texture. Render quality allows
`auto`, `150`, `300`, `600`, `1200`, and `2400` DPI and is used by the Render
screen and PNG/JPG raster exports. Interactive Render caps values above 600 DPI;
1200/2400 DPI are reserved for final raster export preparation.

Vector/PDF sources are rasterized on demand from the original bytes. Interactive
Auto is capped at 600 DPI; export Auto targets the requested output resolution
and is bounded by raster/GPU safety limits. Derived high-resolution blobs are
transient/cacheable browser resources and are never stored in `.carton`.

Raster sources use the original imported pixels and are never AI-upscaled. They
may be downsampled when a target or safety limit is smaller than the source; the
editor continues to show the effective physical DPI so a low-resolution source
is visible before export.

## 7. Layers and rendering

The fixed Layers panel has:

1. Artwork;
2. Dieline;
3. Panel names;
4. Front/Base highlight.

Each has visibility and lock state; Artwork lock prevents pointer, numeric,
keyboard, reset, opacity, and removal transforms. Layers cannot be created or
reordered.

In Edit, artwork outside the panel union is shown at reduced opacity, while the
inside portion is shown at configured opacity. `Show Full Artwork` replaces
that treatment with a single full-opacity unmasked image.

The dieline is derived from panel adjacency:

- boundary edges are solid cut lines;
- shared edges are dashed fold lines.

All six panel names appear in Edit. Panel names and Front/Base highlights are
off in 2D Preview. It clips through one union mask and uses a transparency
checkerboard.

### 3D Preview

Three.js `0.185.1` is loaded only after the user selects `3D Preview`. The scene
is derived exclusively from `BoxNetModel`, `ArtworkModel`, and the normalized
preview Blob:

- one world unit equals one millimetre;
- Front Panel is the root of a recursive hinge tree;
- rigid panel planes rotate around shared fold edges;
- `foldProgress=0` is flat and `foldProgress=1` matches every serialized panel
  basis;
- one CanvasTexture covers the complete net and panel UVs come from canonical
  flat-net coordinates;
- artwork is visible on the exterior, while the interior is white;
- Perspective and Orthographic projections are available, with Perspective as
  the default;
- Technical, Studio, and Photorealistic presets are available, with Studio as
  the default;
- OrbitControls provide rotate, pan, zoom, and focused keyboard panning;
- Raycaster selection uses canonical panel IDs and a DOM inspector.

Open/Fold animate for 400 ms, while the slider writes linear fold progress.
Reduced-motion mode applies Open/Fold immediately. Reset View uses deterministic
isometric framing. The scene renders on demand and uses at most one renderer.
Texture, material, geometry, environment, observer, control, and animation
resources are explicitly retired when replaced or disposed.

Loss or absence of WebGL 2 produces a localized recovery surface with Retry 3D
and Return to 2D. It never clears canonical state or disables export.

## 8. Dimension and topology changes

Changing dimensions with an existing multi-panel layout retains the original
confirmation behavior. If artwork has been modified, one combined confirmation
warns that both layout and placement will reset; a second confirmation is not
shown. Placement is recalculated only after the new six-panel net is complete,
so it fits the final bounds.

Rebuilding topology without changing dimensions preserves the artwork
transform.

## 9. Project persistence

IndexedDB database `carton-builder` stores the current snapshot, original asset,
and editor preview. Autosave is debounced after relevant state changes.
Restoration retains viewport, layers, history, locale metadata, box topology,
asset, and transform.

A downloaded `.carton` is a ZIP with:

```text
manifest.json
project.json
assets/artwork.<ext>
preview/artwork.png
```

The manifest identifies format `carton-builder-project`, version `1`, paths,
creation time, and SHA-256 of the original asset. On import, archive size,
metadata size, asset size, preview size, paths, schema version, and checksum are
validated before state is applied.

Transient decoded bitmaps, PDF proxies, canvas contents, object URLs, Three.js
objects, camera state, fold progress, selection, and scene preset are never
serialized.

Quality settings are serialized in `project.json` and history snapshots. High-
resolution rasterized resources are regenerated locally from the original asset;
they are not added to the archive or undo payload.

## 10. Preflight and export

Preflight is recomputed from canonical state. It reports:

- no artwork (blocking because export is impossible);
- effective raster DPI below 300 (warning);
- panels not fully covered (warning);
- artwork outside the dieline (warning).

Warnings do not block normal export.

### PNG

The complete dieline bounds use the selected vector Render quality; Auto targets
300 DPI. 1200 and 2400 DPI are available when the selected artwork and browser
canvas limits permit them. Artwork is clipped to the
panel union. Pixels outside the union remain transparent. Optional dieline
strokes use solid cut and dashed fold styles.

### JPG

The geometry and resolution match PNG. The canvas is filled white before
drawing.

### SVG

The existing `box-net-<width>x<height>x<depth>mm.svg` contract is unchanged.

### PDF

- page size is the complete dieline bounding box at 72/25.4 points per mm;
- artwork is clipped to the panel union;
- original PDF artwork is embedded as vector page content;
- original PNG/JPEG bytes are embedded without editor-preview downsampling;
- dieline operators are inside a `Dieline` Optional Content Group;
- cut strokes use `/Separation /CutContour`;
- fold strokes are dashed;
- page background is white by PDF page semantics.

Raster export protects the browser with a 32,767-pixel edge limit and a
64-million-pixel total limit. PDF and SVG remain physical-vector paths.

Render displays a centered viewport frame matching the selected Aspect and Long
edge. The frame and the sidebar summary show the exact pixel dimensions that
will be sent to the PNG/JPG render target; the surrounding canvas is inspection
area and is not exported.

## 11. Localization, accessibility, and diagnostics

The persistent EN/RU selector translates the workflow and editor controls.
Dynamic confirmations, status announcements, preflight strings, and common
errors use the active locale.

SVG action buttons have keyboard focus styles and Enter/Space activation. The
box editor has a polite live region for panel add/remove/completion. The PDF page
picker is a native modal dialog, providing Escape handling and modal focus
containment. A `window.resize` rendering fallback is registered when
`ResizeObserver` is unavailable.

The 2D/3D selector is a DOM tablist. All 3D commands are native controls with
visible focus. Fold percentage, selected panel, camera, style, loading, context
loss, and recovery are represented by text and live regions; the WebGL pixels
are not treated as a semantic scene.

Diagnostics are generated only when the user clicks Diagnostics. The downloaded
JSON contains a bounded local action log, coarse browser family, viewport,
dimension state, MIME/pixel/page metadata, and transform values. It excludes
artwork bytes, filenames, checksums, project IDs, and contact identifiers.

## 12. Verification

Vitest covers geometry, basis rotations, panel uniqueness/intersections,
serialization independence, artwork transforms and effective DPI, viewport
math, history limits, cut/fold derivation, file signatures, `.carton`
round-trips, SVG, PDF physical dimensions, OCG resources, and `CutContour`.
It additionally enumerates every complete net reachable by the current model,
checks hinge coincidence and closed basis at multiple fold values, validates
net-space UVs and texture limits, and proves bitmap cleanup.

Playwright covers:

- reference-net completion and integration events;
- PNG load and transform controls;
- locks, keyboard nudge, undo, and redo;
- preview clipping;
- SVG/PNG/PDF/diagnostics downloads;
- `.carton` import and IndexedDB reload;
- EN/RU switching;
- conditional dimension confirmation and cancellation;
- invalid and multi-file input;
- multipage rotated PDF selection and vector export;
- responsive resize with no `ResizeObserver`;
- lazy 3D loading and six-panel scene creation;
- Open/Fold/slider, camera and scene selectors, panel inspector, and Escape;
- canonical-state stability across 3D operations and resize;
- repeated artwork replacement without GPU resource growth;
- WebGL 2 failure with an intact 2D/export workflow.

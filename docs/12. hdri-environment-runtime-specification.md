# HDR Environment & IBL runtime specification

## Scope

Render supports procedural built-in environments and user supplied Radiance
HDR/OpenEXR equirectangular maps. The map is linear-light data: it is decoded
through Three.js `HDRLoader`/`EXRLoader`, converted to a PMREM texture for
lighting, and kept separate from the ordinary sRGB backplate image.

## State contract

`render.lighting.environmentMap` is migrated into project schema v12 (the HDRI
settings migration is v10 → v11; the existing PDF separation migration remains
v11 → v12):

- `source`: `builtin`, `custom`, or `none`;
- `presetId`: catalog id for a procedural environment or a bundled Poly Haven
  environment;
- `assetId`: SHA-256 id for a custom map;
- `usage`: `lighting`, `background`, or `both`;
- `rotation`, `intensity`, `backgroundIntensity`, `backgroundBlur`;
- `resolutionCap`: 1K, 2K (default), or 4K.

Legacy `lighting.environment` values remain supported and continue to provide
the procedural fallback for old projects and failed custom-map loads.

## Built-in environment catalog

The first packaged catalog contains five local 4K Radiance maps from Poly
Haven's abandoned-ruins collection: Abandoned Hall 01, Abandoned Waterworks,
Empty Warehouse 01, Abandoned Workshop, and Peppermint Powerplant. The source
URLs, SHA-256 checksums, and CC0 license reference are recorded in
`public/render-environments/polyhaven/README.md`.

Packaged maps are fetched lazily from the app's own `/render-environments/`
path with a cache hint. This keeps the first Render load light and avoids a
network dependency after deployment. A packaged map is held as a runtime
asset, is not added to project archives, and falls back to the procedural
Neutral Softbox if loading or decoding fails. The five entries are named for
their intended visual role: cool/soft, outdoor overcast, industrial neutral,
warm brick, and warm metal highlights.

## Runtime preparation and resolution ladder

`resolutionCap` is a GPU runtime cap, not an archive or source-file rewrite.
The original Blob, dimensions and SHA-256 remain unchanged. After HDR/EXR
decode, the renderer area-averages the map in linear-light space into an
equirectangular runtime texture and only then sends it to `PMREMGenerator`.
Supported runtime widths are 1024, 2048 (default), and 4096 pixels; height is
kept at the source aspect ratio (normally 512, 1024, or 2048). Maps smaller
than the selected cap are never upsampled.

The device ladder is 4K → 2K → 1K. `maxTextureSize` and the conservative
runtime memory budget are checked before allocation. If no level is viable,
the scene uses Neutral Softbox and keeps the viewport usable. The Render
controls expose requested and effective resolution plus a fallback reason.

Each Render scene owns a bounded LRU cache of at most two entries keyed by
`assetId + resolutionCap`. An entry owns exactly one runtime texture and one
PMREM target. Rotation, intensity, usage and background settings only update
uniforms and never create another texture. Eviction, renderer disposal and
context recovery dispose entries once; stale async loads are ignored by a
generation token.

## Assets and persistence

HDR/EXR uploads are signature checked, size checked (128 MiB), dimension checked,
hashed with SHA-256, and stored as `kind: environment` render assets. Project
archive format v4 keeps the binary in `render-assets/`; `project.json` contains
only settings and the asset id. Archives v1-v3 remain readable. A missing or
invalid custom map falls back to Neutral Softbox and does not blank the viewport.

## Renderer behavior

The Render WebGL scene uses `PMREMGenerator` for `scene.environment`. Rotation,
lighting intensity, background intensity and background blur are independent.
Solid, image, transparent and environment backgrounds are distinct modes;
transparent export hides the environment background while retaining lighting.
GLB export does not embed HDRI/backplate data and emits a preflight warning.

Transient diagnostics (never persisted in project snapshots) include asset id and
source, requested/effective resolution, runtime dimensions, cache hit/miss,
cache occupancy, and fallback reason. A missing custom asset restored from an
archive is reported as `missing-asset` and immediately falls back to Neutral
Softbox. After `webglcontextrestored`, Render rebuilds the active asset using
the current cap and usage settings.

## Verification

- `tests/unit/environmentAssets.test.js` covers signatures, dimensions,
  unsupported uploads and state sanitization.
- `tests/unit/environmentRuntime.test.js` covers 1K/2K/4K selection, no-op
  behavior for smaller maps, linear Float32/HalfFloat downsampling, device and
  memory fallback, and two-entry LRU disposal.
- `tests/unit/projectArchive.test.js` covers v4 round-trip of a custom map.
- Chromium Render E2E covers all five packaged maps, all three caps, custom HDR
  upload, `lighting`/`background`/`both`, context recovery and the 20-cycle
  resource soak. The same smoke subset runs in the existing Edge job.
- A stable bundled-HDRI 2K + `both` visual baseline is the only pixel-sensitive
  map assertion; other maps use state/resource assertions.
- `npm run test:unit`, production build, HDRI E2E/stress, `git diff --check`,
  and `graphify update .` are the Wave 7B release gate.

Wave 7B is complete when every bundled map works at 1K/2K/4K, custom HDR/EXR
survives context restoration, failed assets never leave a blank viewport, and
20 map/cap switches return GPU resources to the two-entry bounded baseline.
Geometry Fidelity remains the separate next Wave 8.

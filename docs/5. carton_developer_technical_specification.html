Technical Design Specification

Carton: 2D box net, artwork placement and 3D folded preview

Спецификация браузерного приложения, в котором развертка коробки является единственным источником геометрической истины, artwork размещается в миллиметрах под dieline, а 3D‑модель и экспорт детерминированно строятся из той же канонической модели.

1. Резюме и ключевые решения

Рекомендуемая реализация — client-first, millimeter-native и 2D-authoritative. Все размеры, положение artwork и структурная геометрия хранятся в миллиметрах. 3D preview, SVG/canvas‑рендеринг и PDF‑экспорт являются адаптерами одной модели, а не независимыми подсистемами.

Source of truth 2D развертка

Панели, линии сгиба, линии реза и artwork transform определяются в flat-net space.

Units Миллиметры

Преобразование в CSS px, raster px и PDF pt выполняется только на границах рендеринга.

3D Derived preview

Three.js складывает жесткие панели через hinge pivots; artwork не редактируется в world space.

2D stack SVG-first

SVG используется для dieline, selection overlay, clipping/masking и точного vector output.

Import / export PDF.js + pdf-lib

PDF.js — preview/rasterization входящих PDF; pdf-lib — 1:1 PDF и embedding страниц.

Persistence Local-first

IndexedDB хранит проекты и Blob‑ресурсы; Service Worker обеспечивает offline-ready shell.

Главный инвариант: запрещено отдельно «подгонять» artwork для 3D. UV каждой панели вычисляется из координат той же плоской развертки, поэтому складывание меняет только 3D transforms, но не texture mapping.

2. Scope продукта и пользовательский workflow

Документ описывает следующий этап существующего приложения Carton: после построения полной развертки пользователь загружает artwork, позиционирует его под dieline, проверяет результат в 3D и экспортирует proof/production-ready geometry в согласованном формате.

1Создать разверткуПользователь формирует 6 панелей с заданными W × H × D.
2ContinueКнопка доступна только при валидном состоянии 6/6.
3Загрузить artworkPNG, JPG или PDF через file picker либо drag-and-drop.
4РазместитьПеремещение и пропорциональное масштабирование в 2D.
5Проверить в 3DСкладывание, orbit/pan/zoom, выбор панели и инспекция.
6ЭкспортироватьPDF 1:1, SVG dieline или PNG proof согласно выбранному профилю.

2.2. MVP scope

  • Один artwork asset на проект.
  • PNG, JPEG и PDF import.
  • File picker и drag-and-drop.
  • Move + proportional scale в 2D.
  • Undo/redo для структурных и artwork‑изменений.
  • 3D folded preview из текущей net model.
  • Локальное сохранение и восстановление проекта.
  • PDF/SVG/PNG export adapters.

2.3. Не входит в MVP

  • Редактирование artwork непосредственно в 3D world space.
  • Многопользовательская работа, комментарии и cloud collaboration.
  • Полноценный prepress: separations, overprint, trapping, ink coverage, spot-color validation.
  • GxP‑валидация, электронные подписи и regulatory approval workflow.
  • Редактирование произвольных векторных объектов из PDF/SVG.
  • Несколько независимых artwork layers, если это отдельно не будет добавлено в scope.

3. Архитектурные принципы и инварианты

Single source of truth

Canvas, SVG DOM и Three.js scene не являются хранилищем состояния. Они только отображают canonical state.

Deterministic rendering

Одинаковый project state должен давать одинаковые 2D, 3D и export outputs.

Flat net first

Панели описываются в плоской системе координат до создания 3D geometry.

Immutable history

Undo/redo хранит snapshots или reversible commands канонического state, а не состояние canvas objects.

Boundary conversion

mm → px/pt/raster px выполняется в render/export adapters; business model не знает про DPI и zoom.

Local processing

Загруженные pharmaceutical artworks не покидают браузер без явного server-side requirement.

Запрещенный anti-pattern: хранить отдельно position/scale для 2D image, UV atlas для Three.js и еще один transform для PDF export. Это гарантированно приведет к расхождению визуализации и печатного файла.

5.2. State management и undo/redo

Undo/redo должен оборачивать canonical project state. Разрешены два подхода: immutable snapshots для MVP или command pattern с inverse operations для крупных файлов. Canvas objects и Three.js objects не сериализуются в history. 

interface HistoryState<T> {
  past: T[];
  present: T;
  future: T[];
}

// Любая domain-команда:
// 1. получает present;
// 2. возвращает новый immutable state;
// 3. очищает future;
// 4. никогда не читает state обратно из SVG/Three.js.

6. Каноническая data model

Ниже приведен минимальный контракт. Он должен быть независим от React, SVG, canvas и Three.js. Blob‑данные artwork хранятся отдельно, а модель содержит стабильный resourceId. 

type Millimeters = number;
type Degrees = number;

type PanelRole =
  | 'front' | 'back' | 'left' | 'right'
  | 'top' | 'bottom' | 'flap' | 'glue-tab';

type EdgeName = 'left' | 'right' | 'top' | 'bottom';

interface PointMm {
  x: Millimeters;
  y: Millimeters;
}

interface PanelModel {
  id: string;
  role: PanelRole;
  xMm: Millimeters;
  yMm: Millimeters;
  widthMm: Millimeters;
  heightMm: Millimeters;
  rotationDeg: Degrees;          // flat-net rotation
  polygon?: PointMm[];           // for non-rectangular flaps
  hingeTo?: string;
  hingeEdge?: EdgeName;
  foldAngleClosedDeg?: Degrees;
  deletable: boolean;
  editorColorRole: 'front' | 'base' | 'default';
}

interface ArtworkModel {
  id: string;
  resourceId: string;            // Blob key in IndexedDB
  sourceType: 'png' | 'jpeg' | 'pdf';
  originalFileName: string;
  sourceWidthPx?: number;
  sourceHeightPx?: number;
  pdfPageIndex?: number;
  xMm: Millimeters;
  yMm: Millimeters;
  widthMm: Millimeters;
  heightMm: Millimeters;
  rotationDeg: Degrees;          // reserved; 0 in MVP unless enabled
  opacity: number;               // default 1
  preservePdfVector: boolean;
}

interface BoxNetModel {
  unit: 'mm';
  boxType: string;
  widthMm: Millimeters;
  heightMm: Millimeters;
  depthMm: Millimeters;
  boardThicknessMm?: Millimeters;
  bleedMm?: Millimeters;
  safeAreaMm?: Millimeters;
  panels: PanelModel[];

  foldPaths: PointMm[][];
}

interface ProjectModel {
  schemaVersion: 1;
  projectId: string;
  projectName: string;
  createdAtIso: string;
  updatedAtIso: string;
  net: BoxNetModel;
  artwork?: ArtworkModel;
}

interface ViewState {
  mode: 'net' | 'artwork' | 'preview3d' | 'export';
  selectedPanelId?: string;
  tool: 'select' | 'pan' | 'zoom' | 'measure' | 'nudge';
  zoom: number;
  panPx: { x: number; y: number };
  foldProgress: number;          // 0..1
}

6.1. Validation invariants

  • net.unit === 'mm' для всех поддерживаемых schema versions.
  • Все dimensions конечны, больше нуля и не являются NaN.
  • Каждый panel.id уникален; каждый hingeTo ссылается на существующую панель.
  • Hinge graph не содержит циклов, если folding implementation основан на parent-child hierarchy.
  • Artwork width/height положительны; aspect ratio соответствует исходному asset с допустимой floating-point погрешностью.
  • View state не сериализуется как часть production geometry, кроме пользовательских UI preferences.

7. Координатные системы и единицы

Каноническая система координат 2D использует origin в левом верхнем углу workspace, X вправо, Y вниз. Это удобно для SVG/canvas и должно быть явно преобразовано при PDF export.

Screen layoutcssPx = mm × 96 / 25.4
PDFpt = mm × 72 / 25.4
Raster exportpx = mm × dpi / 25.4
const MM_PER_INCH = 25.4;
const CSS_PX_PER_INCH = 96;
const PDF_PT_PER_INCH = 72;

export const mmToCssPx = (mm: number) =>
  mm * CSS_PX_PER_INCH / MM_PER_INCH;

export const mmToPt = (mm: number) =>
  mm * PDF_PT_PER_INCH / MM_PER_INCH;

export const mmToRasterPx = (mm: number, dpi: number) =>
  mm * dpi / MM_PER_INCH;

export const topLeftMmToPdfY = (
  yMm: number,
  objectHeightMm: number,
  pageHeightMm: number,
) => pageHeightMm - yMm - objectHeightMm;

Важно: CSS millimeters на мониторе не гарантируют физический размер 1:1. Точность относится к модели и export output. Экранная линейка требует отдельной calibration feature и не должна быть обещана по умолчанию.

7.1. Pointer mapping

Pointer coordinates переводятся из viewport pixels в workspace millimeters через обратную матрицу текущего pan/zoom. Любая операция drag должна работать с одной snapshot‑матрицей, зафиксированной на pointerdown, чтобы исключить drift при обновлении UI.

8. 2D Artwork Editor

8.1. SVG scene composition

Рекомендуемый порядок слоев снизу вверх:

  1. Workspace background / optional grid.
  2. Artwork image group с canonical transform.
  3. Optional panel-union mask или per-panel clip paths для preview/export parity.
  4. Panel fills, если они нужны для режима structure editing.
  5. Cut lines и fold lines.
  6. Selection frame, resize handles, guides и numeric overlays.
<svg viewBox="0 0 {workspaceWidthMm} {workspaceHeightMm}">

    <clipPath id="net-union">
      {panelShapes}
    </clipPath>
  </defs>

  <g id="artwork-layer" clip-path="url(#net-union)">

8.2. Transform behavior

  • Drag изменяет только xMm и yMm.
  • Corner resize изменяет widthMm/heightMm с фиксированным aspect ratio.
  • Resize anchor определяется активным handle; противоположный corner остается неподвижным.
  • Pointer capture обязателен, чтобы resize/drag не прерывался при выходе курсора за SVG.
  • Каждый завершенный gesture создает одну history entry; промежуточные pointermove не должны заполнять history.
  • Состояние selection не меняет exported geometry.

8.3. Маскирование и artwork continuity

В модели artwork остается одним изображением. Для 2D можно использовать один union clipPath либо повторное отображение одного asset под per-panel clips. Для 3D каждая панель использует собственные UV, рассчитанные из единого artwork rectangle; отдельные cropped textures в MVP не рекомендуются.

9. Import pipeline: PNG, JPEG и PDF

9.1. Общий pipeline

  1. Получить File через picker или drop.
  2. Проверить extension, MIME, magic bytes и configured size limit.
  3. Сохранить original Blob в IndexedDB и создать stable resourceId.
  4. Создать preview representation в Web Worker.
  5. Вычислить initial artwork size в mm согласно выбранной fit policy.
  6. Записать ArtworkModel и отобразить его в SVG editor.

9.2. Raster files

Для PNG/JPEG использовать createImageBitmap(), при необходимости нормализовать orientation и ограничить preview texture size в worker через OffscreenCanvas. Original Blob сохраняется без пересжатия. 

// Worker-side outline
self.onmessage = async ({ data }: MessageEvent<Blob>) => {
  const bitmap = await createImageBitmap(data, {
    imageOrientation: 'from-image',
    colorSpaceConversion: 'default',
  });

  const { width, height } = calculatePreviewSize(bitmap.width, bitmap.height);
  const canvas = new OffscreenCanvas(width, height);
  const ctx = canvas.getContext('2d', { alpha: true });
  if (!ctx) throw new Error('2D_CONTEXT_UNAVAILABLE');

  ctx.drawImage(bitmap, 0, 0, width, height);
  const preview = canvas.transferToImageBitmap();
  bitmap.close();
  postMessage(preview, [preview]);
};

9.3. PDF files

PDF.js используется для чтения metadata и raster preview. Original PDF Blob сохраняется отдельно, чтобы export adapter мог при допустимом сценарии встроить исходную PDF page через pdf-lib без повторной rasterization.

Fast preview mode

Выбранная страница PDF rasterize‑ится для 2D editor и Three.js texture. Preview DPI не определяет export DPI.

Print-preserve mode

Исходная PDF page сохраняется и может быть embedded/clipped при PDF export, если transform и masking поддерживаются без разрушения fidelity.

Multipage PDF: поведение не определено исходными требованиями. До начала разработки нужно утвердить page selection policy; рекомендуемый default — page 1 с явным selector, если страниц больше одной.

10. 3D preview: geometry, UV и folding

Каждая панель — отдельная BufferGeometry plane mesh. Панель привязана к Object3D pivot на линии сгиба. Folding выполняется вращением pivot, поэтому panel geometry и UV остаются неизменными.

10.1. UV mapping из flat-net space

interface ArtworkPlacement {
  xMm: number;
  yMm: number;
  widthMm: number;
  heightMm: number;
}

function uvFromNetPoint(
  netX: number,
  netY: number,
  art: ArtworkPlacement,
) {
  const u = (netX - art.xMm) / art.widthMm;
  const v = 1 - (netY - art.yMm) / art.heightMm;
  return { u, v };
}

UV могут выходить за диапазон 0..1, если artwork не покрывает панель. Texture wrapping policy должна предотвращать повтор изображения; рекомендуемый вариант — transparent/empty coverage через canvas texture либо clip-aware texture generation, а не RepeatWrapping.

10.2. Hinge hierarchy

function applyFold(
  panel: PanelModel,
  pivot: THREE.Object3D,
  progress: number,
) {
  const target = THREE.MathUtils.degToRad(panel.foldAngleClosedDeg ?? 0);
  const angle = THREE.MathUtils.lerp(0, target, progress);

  if (panel.hingeEdge === 'left' || panel.hingeEdge === 'right') {
    pivot.rotation.y = angle;
  } else {
    pivot.rotation.x = angle;
  }
}

10.3. Interaction

  • OrbitControls: orbit, pan, zoom; damping допустим только при корректном render loop.
  • Raycaster: выбор панели и синхронизация selectedPanelId с 2D.
  • Panel inspector: role, size, coverage status и local coordinates.
  • Reset View: восстановление согласованного camera preset.
  • No 3D artwork drag: любые точные изменения возвращаются в 2D numeric model.

10.4. Resource lifecycle

  • При замене artwork старые Texture и Material должны быть явно dispose().
  • Retired ImageBitmap должен вызывать close().
  • Texture dimensions/format не изменяются in-place после первого использования; создается новый Texture.
  • Контекст потери WebGL должен обрабатываться без потери canonical project state.

11. Export architecture

Экспорт всегда читает canonical state, а не SVG DOM screenshot и не Three.js framebuffer. Это обеспечивает повторяемость, физический размер и независимость от текущего zoom/camera.

PNGProof, thumbnail, 3D snapshotНетРазмер в пикселях должен явно вычисляться из выбранного DPI

11.1. PDF export

  • Page size определяется net bounds + утвержденные margins/bleed в PDF points.
  • Artwork рисуется первым; cut/fold lines — поверх artwork.
  • Top-left Y преобразуется в PDF bottom-left Y.
  • Dieline сохраняется vector paths.
  • При raster artwork используется original/high-resolution source, а не preview texture.
  • При print-preserve PDF используется embedded page/clip, когда transform поддерживается.
const page = pdf.addPage([
  mmToPt(exportWidthMm),
  mmToPt(exportHeightMm),
]);

page.setTrimBox(
  mmToPt(trimXmm),
  mmToPt(trimYmm),
  mmToPt(trimWidthMm),
  mmToPt(trimHeightMm),
);

// 1. draw/clip artwork from canonical ArtworkModel
// 2. draw vector cut paths
// 3. draw vector fold paths
// 4. attach metadata and save

Production caveat: PDF 1:1 еще не означает print-production compliance. Spot colors, overprint, line naming, PDF/X profile, embedded fonts, ICC profiles, bleed and safety rules должны быть отдельным утвержденным prepress scope.

12. Project persistence, storage и offline

12.1. IndexedDB

Рекомендуемые object stores:

StoreKeyДанные

12.2. Schema migrations

Каждый ProjectModel содержит schemaVersion. Миграции являются чистыми функциями vN → vN+1, покрыты unit tests и никогда не модифицируют original saved record in-place до успешной валидации результата.

12.3. Service Worker

Service Worker кэширует application shell и статические dependencies, но не должен автоматически отправлять или синхронизировать artwork. Развертывание требуется по HTTPS. Обновление версии должно избегать потери unsaved project state.

13. Нефункциональные требования

13.1. Performance и memory

  • 2D editor остается vector-first; rasterization применяется только к artwork preview.
  • Preview texture resolution ограничивается device-aware policy; export использует отдельный high-quality path.
  • Основной UI не блокируется PDF rasterization и large-image normalization — эти операции выполняются в worker.
  • Количество WebGL draw calls для одной коробки минимально; каждая панель может быть отдельным mesh без необходимости instancing.
  • Repeated artwork replacement не должен приводить к монотонному росту GPU/heap memory.

13.2. Security и privacy

  • Обработка файлов локальная по умолчанию.
  • Remote URL import отсутствует в MVP; это исключает основной риск tainted canvas/CORS.
  • Object URLs вызывают URL.revokeObjectURL() после замены/закрытия проекта.
  • File name отображается как text content, а не вставляется через HTML.
  • Парсинг PDF выполняется в sandboxed library context; errors не раскрывают локальные пути пользователя.

13.3. Accessibility

  • Toolbar, buttons, tabs и inspector реализуются стандартными DOM controls.
  • Canvas/SVG/WebGL дополняются текстовым selection/status summary.
  • Все действия artwork доступны с клавиатуры, включая move/nudge и proportional resize через numeric fields.
  • Drop zone имеет keyboard alternative и корректный accessible name.
  • Ошибки и завершение импорта объявляются через ARIA live region.
  • Фокус видим; shortcut не конфликтует с browser/assistive technology conventions.

13.4. Browser support

Базовая реализация должна использовать WebGL2‑совместимый Three.js renderer. WebGPU может быть progressive enhancement, но не единственным путем. Конкретная browser matrix должна быть зафиксирована до release hardening.

15. Рекомендуемый план реализации

Phase A Canonical 2D foundation

Model, validation, units, state/history, SVG dieline, upload, artwork move/scale, IndexedDB save.

Phase B Derived 3D preview

Panel BufferGeometry, UV mapping, hinge hierarchy, fold progress, camera controls, selection sync.

Phase C Import/export hardening

PDF page handling, vector-preserve path, PDF/SVG/PNG export, accessibility, stress and release testing.

15.1. Dependency order

  1. Зафиксировать canonical schema и box-style topology.
  2. Покрыть geometry/units тестами.
  3. Реализовать Stage 2 artwork editing без 3D.
  4. Добавить local persistence и undo/redo.
  5. Создать Three.js adapter и UV mapping.
  6. Добавить PDF import modes и export adapters.
  7. Провести performance, accessibility и browser hardening.

Delivery rule: 3D не следует начинать до стабилизации canonical 2D model. Иначе 3D‑слой неизбежно начнет компенсировать ошибки структуры и станет вторым источником истины.

16. Definition of Done / Acceptance criteria

IDКритерий приемки
AC-001При любом screen zoom числовые X/Y/W/H artwork в mm не изменяются.
AC-002После proportional resize вычисленный aspect ratio совпадает с исходным в пределах согласованного epsilon.
AC-003Один и тот же flat-net point отображает один и тот же artwork pixel в 2D и на соответствующей 3D panel.
AC-004Fold progress меняет только transforms pivots и не изменяет UV/ArtworkModel.
AC-005PDF export page size, dieline dimensions и artwork placement воспроизводятся из project state без чтения SVG DOM.
AC-006Undo после artwork replacement восстанавливает предыдущий asset и transform.
AC-007Reload приложения восстанавливает проект из IndexedDB без потери original file Blob.
AC-008Неподдерживаемый/поврежденный файл не ломает текущий проект и дает actionable error.
AC-009Все основные действия доступны без мыши через DOM controls и keyboard interaction.
AC-010Repeated asset replacement освобождает retired ImageBitmap, Texture и Material resources.

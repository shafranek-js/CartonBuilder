# 8. 3D и HTML внутри PDF: исследование возможностей

Дата: 2026-08-01. Тема: можно ли из браузерного приложения (CartonBuilder) получить PDF,
внутри которого отображается интерактивная 3D-коробка или «живой» HTML-контейнер.

## Итоговый вердикт

| Вариант | Реализуемость в браузере | Результат |
|---|---|---|
| «Живой» HTML внутри страницы PDF | **Невозможно** | PDF не умеет рендерить HTML |
| Интерактивный 3D-объект внутри PDF (U3D/PRC) | **Очень сложно** (нет JS-библиотек; либо коммерческий SDK, либо свой U3D-сериализатор) | Работает только в Acrobat/Reader |
| Статичный рендер коробки + интерактивный HTML **вложением** | **Легко** (pdf-lib `attach()`) | HTML открывается отдельно от PDF |
| Статичное фотореалистичное изображение коробки на странице PDF | **Легко** (уже есть 3D-сцена + рендер в PNG) | Работает везде |

**Рекомендация для CartonBuilder**: вариант «PDF с фотореалистичным превью коробки на
странице + интерактивный HTML-файл вложением» — единственный практичный браузерный путь.

---

## 1. HTML внутри PDF — невозможно

- HTML и PDF — разные модели визуализации; ни один просмотрщик PDF (включая Acrobat)
  не отображает живой HTML на странице.
- HTML можно только **вложить** файлом и открывать отдельно.
  Источник: [Stack Overflow — can you embed an HTML webpage in a PDF](https://stackoverflow.com/questions/10571381).
- Клиентские конвертеры HTML→PDF (html2canvas, jsPDF `.html()` и т.п.) только
  **растеризуют** HTML в графику страницы; «живости» нет.
- PDF Association отдельно анализирует несовместимость HTML и PDF:
  [HTML and PDF, best of Frenemies](https://pdfa.org/presentation/html-and-pdf-best-of-frenemies/).

## 2. 3D-аннотации PDF (U3D / PRC)

- Спецификация: ISO 32000-1, 3D-аннотация `/Subtype /3D` с ключами `/3DD` (3D-поток,
  `/Subtype /U3D` или `/Subtype /PRC`), `/3DA` (активация), `/3DV` (вид, матрица камеры
  `/C2W`), `/AP` (2D-фолбэк-изображение для просмотрщиков без 3D).
- Форматы: **U3D** (ECMA-363) — меши, текстуры, анимация; **PRC** (ISO 14739-1) — также
  точная CAD-геометрия.
- Поддержка просмотра: **только Acrobat/Reader** (и несколько десктопных — PDF-XChange,
  Bluebeam). Ни один браузерный просмотрщик не рендерит 3D-аннотации:
  [pdf.js #3254 — 3D PDF support (закрыт без реализации)](https://github.com/mozilla/pdf.js/issues/3254);
  даже коммерческий WASM-WebViewer Apryse показывает 3D-страницы чёрными
  [webviewer-ui #1051](https://github.com/ApryseSDK/webviewer-ui/issues/1051).
- Ключевой вывод: **даже если получить валидный 3D-PDF, пользователь увидит коробку
  только в Acrobat**, в Chrome/Edge — только 2D-фолбэк.

## 3. JS-библиотеки для генерации U3D / PRC — отсутствуют

- npm: `u3d` / `u3d-loader` — это про Unity3D, не про формат PDF; `aspose-cad` (WASM)
  только **читает** U3D; сериализаторов нет.
- GitHub: только мёртвые или не-JS проекты (`fig2u3d` — MATLAB, 2021; `PdfHandy.Net`,
  `U3D-2-PDF` — 2016–2017).
- `pdf-lib`, `jsPDF`, `pdfmake`, `pdfkit`, `pdfjs-dist` — **нулевая** поддержка 3D
  (pdf-lib: только `attach()`, `addJavaScript()`, изображения/шрифты/формы).
- Коммерческие: Apryse PDFNet (единственный поддерживаемый SDK с образцом встраивания
  U3D — [u3dtest sample](https://docs.apryse.com/core/samples/u3dtest)), Aspose, и
  десктопные конвертеры (Tetra4D, SimLab, Okino, PDF3D SDK).
- WASM-портов библиотек-писателей U3D не найдено.

## 4. Вложения в PDF — стандарт и работает

- Спецификация: потоки `/EmbeddedFile` (§7.11), словари `/Filespec` (§12.3.3),
  аннотации `/Subtype /FileAttachment` (§12.5.6.15), коллекция вложений
  `/Names /EmbeddedFiles` (§7.7.4).
- pdf-lib: `pdfDoc.attach(bytes, name, { mimeType, description, creationDate, modificationDate })`
  — [документация PDFDocument#attach](https://pdf-lib.js.org/docs/api/classes/pdfdocument#attach).
  Вложения видны в панели «Вложения» Acrobat; поддерживается любой тип (в т.ч. `.html`).

## 5. JavaScript в PDF (Acrobat JS)

- PDF может содержать ECMAScript (спид-база SpiderMonkey): скрипты документа, события
  полей/аннотаций; pdf-lib отдаёт это через `pdfDoc.addJavaScript()`.
- Есть «3D JavaScript» API Acrobat для **манипуляции существующего** 3D-объекта
  (поворот и т.п.), но:
  - «API не может создавать новые 3D-аннотации и менять модели» —
    [Stack Overflow #59783163](https://stackoverflow.com/questions/59783163);
  - в PDF-JS нет DOM/WebGL/canvas — рендерить 3D «с нуля» нельзя;
  - pdf.js не исполняет Acrobat-JS.

## 6. Практические конвейеры «3D-модель → PDF» (вне браузера)

- Blender без U3D-экспорта ([Blender StackExchange #24648](https://blender.stackexchange.com/questions/24648/export-3d-model-from-blender-to-u3d-for-use-in-pdf-file));
  маршруты — Daz Studio, MeshLab, платные плагины (SimLab, Okino).
- Программно: iText (Java), LaTeX `media9` (U3D+PRC), MATLAB `fig2u3d`, Apryse PDFNet
  (Node.js), PDF3D SDK, PROSTEP.
- Браузерных бесплатных конвейеров не существует.

## 7. Выводы для CartonBuilder

1. **«HTML-контейнер внутри PDF»** — исключено на уровне формата.
2. **Интерактивный 3D-PDF** — только коммерческий SDK (Apryse) или собственный
   U3D-сериализатор (~несколько тысяч строк, бинарные блоки ECMA-363); результат всё
   равно виден лишь в Acrobat — для приложения это нецелесообразно.
3. **Практичный вариант**: PDF, где на странице — статичное фотореалистичное
   изображение собранной коробки (рендер текущей 3D-сцены в высоком разрешении),
   а интерактивный HTML-файл коробки приложен к PDF через `pdfDoc.attach()`.
   Пользователь получает один `.pdf`, открывающийся везде, плюс интерактивную
   копию, доступную из вложений.

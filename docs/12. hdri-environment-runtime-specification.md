# HDR Environment & IBL runtime specification

## Scope

Render supports procedural built-in environments and user supplied Radiance
HDR/OpenEXR equirectangular maps. The map is linear-light data: it is decoded
through Three.js `HDRLoader`/`EXRLoader`, converted to a PMREM texture for
lighting, and kept separate from the ordinary sRGB backplate image.

## State contract

`render.lighting.environmentMap` is migrated into project schema v12 (the HDRI
settings migration is v10 → v11; the existing PDF separation migration remains
v11 → v12):

- `source`: `builtin`, `custom`, or `none`;
- `presetId`: catalog id for a procedural environment or a bundled Poly Haven
  environment;
- `assetId`: SHA-256 id for a custom map;
- `usage`: `lighting`, `background`, or `both`;
- `rotation`, `intensity`, `backgroundIntensity`, `backgroundBlur`;
- `resolutionCap`: 1K, 2K (default), or 4K.

Legacy `lighting.environment` values remain supported and continue to provide
the procedural fallback for old projects and failed custom-map loads.

## Built-in environment catalog

The first packaged catalog contains five local 4K Radiance maps from Poly
Haven's abandoned-ruins collection: Abandoned Hall 01, Abandoned Waterworks,
Empty Warehouse 01, Abandoned Workshop, and Peppermint Powerplant. The source
URLs, SHA-256 checksums, and CC0 license reference are recorded in
`public/render-environments/polyhaven/README.md`.

Packaged maps are fetched lazily from the app's own `/render-environments/`
path with a cache hint. This keeps the first Render load light and avoids a
network dependency after deployment. A packaged map is held as a runtime
asset, is not added to project archives, and falls back to the procedural
Neutral Softbox if loading or decoding fails. The five entries are named for
their intended visual role: cool/soft, outdoor overcast, industrial neutral,
warm brick, and warm metal highlights.

## Assets and persistence

HDR/EXR uploads are signature checked, size checked (128 MiB), dimension checked,
hashed with SHA-256, and stored as `kind: environment` render assets. Project
archive format v4 keeps the binary in `render-assets/`; `project.json` contains
only settings and the asset id. Archives v1-v3 remain readable. A missing or
invalid custom map falls back to Neutral Softbox and does not blank the viewport.

## Renderer behavior

The Render WebGL scene uses `PMREMGenerator` for `scene.environment`. Rotation,
lighting intensity, background intensity and background blur are independent.
Solid, image, transparent and environment backgrounds are distinct modes;
transparent export hides the environment background while retaining lighting.
GLB export does not embed HDRI/backplate data and emits a preflight warning.

- `tests/unit/projectArchive.test.js` covers v4 round-trip of a custom map.
- `npm run build` verifies the HDR/EXR loader and renderer bundle.

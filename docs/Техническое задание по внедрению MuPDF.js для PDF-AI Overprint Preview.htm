Техническое задание: внедрение MuPDF.js для PDF/AI Overprint Preview

1. Цель внедрения

Приложение должно:

  1. Принимать файлы .pdf и .ai.
  2. Отображать PDF с учётом:

o   overprint fill и overprint stroke;

o   Overprint Mode 0/1;

o   CMYK;

o   spot colors;

o   Separation и DeviceN;

o   transparency groups;

o   knockout и isolated groups;

o   ICC-профилей и PDF Output Intent настолько, насколько это поддерживает MuPDF.

  1. Показывать результат, сопоставимый по поведению с:

o   Adobe Illustrator → View → Overprint Preview;

o   Adobe Acrobat Pro → Output Preview → Simulate Overprinting.

  1. Не растрировать и не изменять исходный PDF/AI.
  2. Использовать растровое изображение только как экранный preview.
  3. Выполнять тяжёлый PDF-рендеринг вне основного UI-потока.

2. Критически важное ограничение MuPDF.js

MuPDF Core поддерживает три режима обработки spot colors и overprint:

·         0 — spot rendering и overprint simulation отключены;

·         1 — overprint simulation;

·         2 — полный spot rendering с отдельными цветовыми каналами.

В mutool draw это управляется параметром -M, причём режим 1 указан как режим overprint simulation по умолчанию.

Однако публичный JavaScript-метод:

PDFPage.toPixmap(matrix, colorspace, alpha, showExtras, usage, box)

не содержит документированного параметра overprintMode. Он позволяет задать матрицу, выходное цветовое пространство, alpha, отображение annotations/widgets, режим View/Print и page box, но не режим 0/1/2.

Следствие

Разработчик не должен начинать полную интеграцию с предположением:

«Раз MuPDF Core поддерживает overprint, значит стандартный npm-пакет гарантированно даёт управляемый Overprint Preview».

Сначала необходимо выполнить отдельный Capability Spike:

  1. Установить официальный пакет mupdf.
  2. Отрендерить специально подготовленные overprint-тесты через стандартный PDFPage.toPixmap.
  3. Сравнить результат с Illustrator и Acrobat.
  4. Определить:

o   активна ли overprint simulation в стандартной WASM-сборке;

o   корректно ли обрабатываются обязательные тестовые сценарии;

o   нужен ли пользователю переключатель Overprint Preview ON/OFF;

o   требуется ли отдельное отображение красочных сепараций.

Решение после Capability Spike

Сценарий A — стандартный MuPDF.js подходит

Использовать стандартный npm-пакет, когда:

·         приложение всегда должно показывать artwork с overprint simulation;

·         стандартный рендер совпадает с эталонным поведением Adobe;

·         переключатель ON/OFF не требуется;

·         отдельные каналы spot colors пока не нужны.

Сценарий B — нужен custom WASM wrapper

Собственная WASM-сборка потребуется, когда:

·         нужен переключатель Overprint Preview ON/OFF;

·         нужно выбирать режимы 0, 1, 2;

·         нужна панель сепараций;

·         стандартный toPixmap не активирует ожидаемый режим;

·         требуется более глубокое управление proofing и цветоделением.

В custom wrapper следует открыть минимальный API к тому же механизму MuPDF Core, который используется параметром mutool draw -M. Нельзя самостоятельно эмулировать overprint на стороне JavaScript.

3. Используемый пакет

Использовать официальный пакет:

npm install mupdf --save-exact

Не использовать пакет:

mupdf-js

Официальный пакет называется mupdf; старый пакет mupdf-js объявлен устаревшим. MuPDF.js работает через WebAssembly, является ESM-only модулем и включает TypeScript definitions.

После успешного Capability Spike необходимо:

·         зафиксировать точную версию в package.json;

·         сохранить lock-файл;

·         не обновлять MuPDF автоматически;

·         выполнять regression tests перед каждым обновлением;

·         логировать используемую версию MuPDF в диагностике приложения.

Пример:

{
  "dependencies": {
    "mupdf": "ТОЧНАЯ_ПРОТЕСТИРОВАННАЯ_ВЕРСИЯ"
  }
}

Для TypeScript использовать ESM-compatible конфигурацию. Например:

{
  "compilerOptions": {
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "target": "ES2022",
    "strict": true
  }
}

Главный принцип

MuPDF отвечает за интерпретацию PDF:

·         transparency;

·         blending;

·         overprint;

·         color spaces;

·         masks;

·         shadings;

·         fonts;

·         images;

·         spot colors.

Приложение отвечает только за:

·         загрузку;

6. Web Worker обязателен

PDF decoding и rendering нельзя выполнять в основном потоке браузера.

MuPDF является вычислительно тяжёлым WASM-модулем. Официальная документация рекомендует Web Workers, чтобы загрузка и рендеринг документов не блокировали интерфейс.

Базовая модель

Для первого релиза:

·         один Worker на один открытый документ;

·         один активный документ на Worker;

·         закрытие документа уничтожает Worker либо полностью освобождает его ресурсы.

Позже можно создать Worker Pool, но только после стабильной реализации memory lifecycle.

Протокол Worker

type WorkerRequest =
  | OpenDocumentRequest
  | AuthenticateRequest
  | GetDocumentInfoRequest
  | RenderPageRequest
  | CloseDocumentRequest
  | CancelRenderRequest;

interface OpenDocumentRequest {
  type: "open-document";
  requestId: string;
  documentId: string;
  bytes: ArrayBuffer;
  fileName: string;
  mimeHint?: string;
}

interface RenderPageRequest {
  type: "render-page";
  requestId: string;
  documentId: string;
  pageIndex: number;

  zoom: number;
  devicePixelRatio: number;

  pageBox:
    | "MediaBox"
    | "CropBox"
    | "BleedBox"

    | "ArtBox";

  usage: "View" | "Print";
  showExtras: boolean;

7. Открытие PDF и AI

7.1 Проверять содержимое, а не расширение

Расширение .pdf или .ai является только подсказкой.

Порядок проверки:

1.      Получить File.

2.      Проверить допустимый размер.

3.      Прочитать ArrayBuffer.

4.      Передать содержимое в MuPDF.

5.      Проверить, распознаётся ли содержимое как PDF.

6.      Попытаться открыть документ.

7.      Проверить document.isPDF().

MuPDF имеет методы распознавания содержимого и открытия PDF из ArrayBuffer.

Не следует доверять только:

file.type
file.name.endsWith(".pdf")
file.name.endsWith(".ai")

7.2 Работа с AI

MuPDF не является нативным парсером Illustrator PGF.

AI-файл можно открыть только тогда, когда при сохранении была включена опция:

Create PDF Compatible File

Adobe указывает, что AI использует PDF и PGF, а включение этой опции добавляет в AI-файл PDF syntax, доступный приложениям, распознающим PDF.

Алгоритм:

async function classifyArtworkFile(file: File): Promise<{
  kind: "pdf" | "pdf-compatible-ai";
  bytes: ArrayBuffer;
}> {
  const bytes = await file.arrayBuffer();

  const recognized = mupdf.Document.recognizeContent(
    bytes,
    "application/pdf"
  );

  if (!recognized) {
    throw new ArtworkImportError(
      file.name.toLowerCase().endsWith(".ai")
        ? "AI_NOT_PDF_COMPATIBLE"
        : "UNSUPPORTED_OR_INVALID_PDF"
    );
  }

  return {
    kind: file.name.toLowerCase().endsWith(".ai")
      ? "pdf-compatible-ai"
      : "pdf",
    bytes
  };
}

Дополнительно всё равно требуется фактическая попытка openDocument, поскольку распознавание формата ещё не доказывает целостность документа.

Сообщение пользователю

Этот AI-файл не содержит PDF-compatible representation.

Пересохраните файл в Adobe Illustrator с включённой опцией:
Create PDF Compatible File.

Приложение не должно заявлять поддержку:

·         нативного редактирования AI;

·         Illustrator-specific PGF;

·         восстановления AI layers, не представленных в PDF-части;

·         полной совместимости с Illustrator editing model.

9. Базовый Worker renderer

Ниже приведён framework-neutral skeleton.

// mupdf.worker.ts
import * as mupdf from "mupdf";

type PageBox =
  | "MediaBox"
  | "CropBox"
  | "BleedBox"
  | "TrimBox"
  | "ArtBox";

interface OpenMessage {
  type: "open-document";
  requestId: string;
  documentId: string;
  bytes: ArrayBuffer;
}

interface RenderMessage {
  type: "render-page";
  requestId: string;
  documentId: string;
  pageIndex: number;
  zoom: number;
  devicePixelRatio: number;
  pageBox: PageBox;
}

interface CloseMessage {
  type: "close-document";
  requestId: string;
  documentId: string;
}

type IncomingMessage = OpenMessage | RenderMessage | CloseMessage;

let currentDocument: mupdf.Document | null = null;
let currentDocumentId: string | null = null;

self.onmessage = (event: MessageEvent<IncomingMessage>) => {
  const message = event.data;

  try {
    switch (message.type) {
      case "open-document":
        openDocument(message);
        break;

      case "render-page":
        renderPage(message);
        break;

      case "close-document":
        closeDocument(message);
        break;
    }
  } catch (error) {
    postWorkerError(message.requestId, error);
  }
};

function openDocument(message: OpenMessage): void {
  destroyCurrentDocument();

  const document = mupdf.Document.openDocument(
    message.bytes,
    "application/pdf"
  );

  if (!document.isPDF()) {
    document.destroy();
    throw new Error("The supplied file is not a PDF document.");
  }

  currentDocument = document;
  currentDocumentId = message.documentId;

  self.postMessage({
    type: "document-opened",
    requestId: message.requestId,
    documentId: message.documentId,
    pageCount: document.countPages(),
    needsPassword: document.needsPassword()
  });
}

function renderPage(message: RenderMessage): void {
  if (
    !currentDocument ||
    currentDocumentId !== message.documentId
  ) {
    throw new Error("Requested document is not open.");
  }

  if (currentDocument.needsPassword()) {
    throw new Error("Document password is required.");
  }

  const loadedPage = currentDocument.loadPage(message.pageIndex);

  if (!(loadedPage instanceof mupdf.PDFPage)) {
    loadedPage.destroy();
    throw new Error("Loaded page is not a PDF page.");
  }

  const page = loadedPage;

  let pixmap: mupdf.Pixmap | null = null;

  try {
    /*
     * PDF coordinates use 72 points per inch.
     * CSS reference resolution is normally 96 pixels per inch.
     */
    const cssPixelsPerPoint = 96 / 72;

    const renderScale =
      cssPixelsPerPoint *
      Math.max(0.01, message.zoom) *
      Math.max(1, message.devicePixelRatio);

    /*
     * IMPORTANT:
     * The standard public MuPDF.js API does not expose
     * overprintMode 0/1/2 here.
     *
     * The actual overprint behaviour must be verified by
     * the Capability Spike. If explicit control is needed,
     * use a custom WASM wrapper.
     */
    pixmap = page.toPixmap(
      mupdf.Matrix.scale(renderScale, renderScale),
      mupdf.ColorSpace.DeviceRGB,
      false,                  // opaque page preview
      false,                  // exclude annotations and widgets
      "Print",                // print-oriented rendering usage
      message.pageBox
    );

    const packedPixels = convertPixmapToRgba(pixmap);
    const bounds = pixmap.getBounds();

    self.postMessage(
      {
        type: "page-rendered",
        requestId: message.requestId,
        documentId: message.documentId,
        pageIndex: message.pageIndex,

        width: pixmap.getWidth(),
        height: pixmap.getHeight(),
        stride: pixmap.getWidth() * 4,
        components: 4,

        originX: bounds[0],
        originY: bounds[1],

        pixels: packedPixels.buffer
      },
      [packedPixels.buffer]
    );
  } finally {
    pixmap?.destroy();
    page.destroy();
  }
}

function convertPixmapToRgba(
  pixmap: mupdf.Pixmap
): Uint8ClampedArray {
  const width = pixmap.getWidth();
  const height = pixmap.getHeight();
  const sourceStride = pixmap.getStride();
  const components = pixmap.getNumberOfComponents();

  const source = pixmap.getPixels();
  const target = new Uint8ClampedArray(width * height * 4);

  if (components !== 3 && components !== 4) {
    throw new Error(
      `Unexpected RGB pixmap component count: ${components}`
    );
  }

  for (let y = 0; y < height; y++) {
    const sourceRow = y * sourceStride;
    const targetRow = y * width * 4;

    for (let x = 0; x < width; x++) {
      const sourceOffset = sourceRow + x * components;
      const targetOffset = targetRow + x * 4;

      target[targetOffset] = source[sourceOffset];
      target[targetOffset + 1] = source[sourceOffset + 1];
      target[targetOffset + 2] = source[sourceOffset + 2];
      target[targetOffset + 3] =
        components === 4 ? source[sourceOffset + 3] : 255;
    }
  }

  return target;
}

function closeDocument(message: CloseMessage): void {
  if (message.documentId === currentDocumentId) {
    destroyCurrentDocument();
  }

  self.postMessage({
    type: "document-closed",
    requestId: message.requestId,
    documentId: message.documentId
  });
}

function destroyCurrentDocument(): void {
  currentDocument?.destroy();
  currentDocument = null;
  currentDocumentId = null;
}

function postWorkerError(
  requestId: string,
  error: unknown
): void {
  self.postMessage({
    type: "worker-error",
    requestId,
    message:
      error instanceof Error
        ? error.message
        : String(error)
  });
}

MuPDF предоставляет raw pixel data, размеры, число компонентов и stride через объект Pixmap. Pixmap также специально содержит координаты, позволяющие использовать его как тайл страницы.

10. Отображение результата на Canvas

function drawRenderedPage(
  canvas: HTMLCanvasElement,
  response: RenderPageResponse
): void {
  canvas.width = response.width;
  canvas.height = response.height;

  const context = canvas.getContext("2d");

  if (!context) {
    throw new Error("Canvas 2D context is unavailable.");
  }

  const pixels = new Uint8ClampedArray(response.pixels);

  const imageData = new ImageData(
    pixels,
    response.width,
    response.height
  );

  context.putImageData(imageData, 0, 0);
}

Не выполнять рендеринг заново при каждом движении мыши

Во время pan/zoom:

1.      Мгновенно трансформировать уже существующий Canvas/ImageBitmap.

2.      Не вызывать MuPDF на каждом pointermove.

3.      После завершения взаимодействия выполнить debounce.

4.      Запросить изображение более высокого разрешения.

5.      Незаметно заменить временный preview.

Рекомендуемый порядок:

Pointer down
    ↓
Transform existing bitmap
    ↓
Pointer move
    ↓
Transform existing bitmap
    ↓
Pointer up / wheel settles
    ↓
Debounce
    ↓
Request high-resolution MuPDF render
    ↓
Replace bitmap

12. Режим View или Print

PDFPage.toPixmap принимает параметр usage:

View
Print

Для overprint-oriented preview первоначально использовать:

"Print"

Но Capability Spike должен сравнить результаты обоих режимов.

Критерий выбора:

·         использовать Print, если он лучше соответствует Acrobat Output Preview;

·         использовать View, только если тесты докажут более корректное поведение для конкретной сборки.

Выбор нельзя делать только по названию параметра.

13. Color spaces

MuPDF поддерживает:

·         DeviceGray;

·         DeviceRGB;

·         DeviceCMYK;

·         Lab;

·         Separation;

·         DeviceN;

·         пользовательские ICC color spaces.

JavaScript API позволяет создать ColorSpace из ICC profile, а DeviceN может иметь произвольное число компонентов.

Для браузерного preview

Итоговый pixmap должен быть:

mupdf.ColorSpace.DeviceRGB

MuPDF должен сначала выполнить PDF rendering и overprint simulation, а затем сформировать RGB preview для Canvas.

Не следует:

1.      Извлекать CMYK-значения самостоятельно.

2.      Переводить каждый PDF-объект в RGB в JavaScript.

3.      Использовать CSS mix-blend-mode: multiply.

4.      Заменять spot colors обычными CSS-цветами.

5.      Реализовывать overprint через наложение Canvas layers.

Важное сообщение пользователю

Даже корректная overprint simulation не является сертифицированной цветопробой.

В UI следует указывать:

Overprint simulation enabled.
Monitor preview is not a contract color proof.

Причины:

·         профиль монитора;

·         калибровка;

·         browser color management;

·         яркость экрана;

·         цвет бумаги;

·         особенности печатного процесса.

Не следует называть функцию:

Certified soft proof
Exact print color
100% Illustrator color match

Корректное название:

Overprint Preview
MuPDF overprint simulation

14. Поддержка режима Overprint ON/OFF

15. Требования к custom WASM wrapper

Custom wrapper должен быть минимальным.

Пример желаемого интерфейса:

interface NativeRenderOptions {
  overprintMode: 0 | 1 | 2;
}

Или:

setOverprintRenderingMode(mode: 0 | 1 | 2): void;

Необходимо:

1.      Использовать официальный исходный код MuPDF.

2.      Зафиксировать конкретный MuPDF tag/commit.

3.      Найти код, обрабатывающий mutool draw -M.

4.      Открыть только требуемую настройку.

5.      Собрать WASM воспроизводимым build process.

6.      Хранить build scripts в репозитории.

7.      Автоматически запускать reference tests.

8.      Добавлять номер MuPDF и wrapper build в diagnostics.

9.      Не модифицировать PDF interpretation logic без необходимости.

10. Согласовать права на custom build с лицензией Artifex.

Не следует самостоятельно интерпретировать PDF-операторы:

/OP
/op
/OPM

Эти параметры зависят от:

·         текущего graphics state;

·         типа объекта;

·         цветового пространства;

·         transparency group;

·         knockout;

·         colorants;

·         DeviceN tint transforms;

·         blending space.

Простая замена blend mode на Multiply не является overprint simulation.

16. Производительность

16.1 Progressive rendering

Использовать два качества:

Draft

·         небольшое разрешение;

·         быстрый preview;

·         применяется во время взаимодействия.

Final

·         соответствует текущему zoom и DPR;

·         создаётся после завершения взаимодействия.

Пример:

Open document
    ↓
Draft preview
    ↓
User can immediately interact
    ↓
Final preview replaces Draft

16.2 Ограничение размера pixmap

Перед рендерингом вычислять:

const pixelCount = width * height;

Ввести максимальный размер одного pixmap. Начальное инженерное ограничение:

30–40 megapixels per render

Окончательный лимит определить нагрузочными тестами.

При превышении лимита:

·         не создавать гигантский full-page pixmap;

·         переключаться на tiled rendering;

·         либо уменьшать draft resolution.

16.3 Tiled rendering

Для больших упаковочных artwork использовать тайлы:

1024 × 1024 px
или
2048 × 2048 px

Ключ кеша:

interface RenderCacheKey {
  documentHash: string;
  pageIndex: number;
  pageBox: string;

  zoomBucket: number;
  devicePixelRatio: number;

  tileX: number;
  tileY: number;
  tileWidth: number;
  tileHeight: number;

  overprintMode: number;
  usage: "View" | "Print";

  layerStateHash?: string;
  profileHash?: string;
  rendererVersion: string;
}

Добавить overscan 1–2 pixels по краям тайлов для предотвращения визуальных швов.

16.4 Cache

Использовать LRU cache.

При удалении элемента:

imageBitmap.close();

Также необходимо:

·         удалить связанные pixel buffers;

·         освободить object URLs;

·         убрать references из Map;

·         учитывать общий объём памяти, а не только число элементов.

17. Memory management

MuPDF.js использует WebAssembly memory, которая автоматически не освобождается JavaScript garbage collector. Каждый объект MuPDF необходимо явно уничтожать через .destroy().

Обязательно уничтожать:

·         Document;

·         PDFDocument;

·         Page;

·         PDFPage;

·         Pixmap;

·         Buffer;

·         DisplayList;

·         StructuredText;

·         пользовательские ColorSpace;

·         другие временные объекты MuPDF.

Использовать:

try {
  // work
} finally {
  object.destroy();
}

Копировать pixel data до вызова:

pixmap.destroy();

После уничтожения Pixmap нельзя хранить view на его WASM memory.

Memory regression test

Повторить минимум 50–100 циклов:

Open
Render
Zoom
Render
Close

После теста память не должна расти линейно.

18. Отмена рендеринга

Необходимо присваивать каждому render request уникальный requestId.

const requestId = crypto.randomUUID();

Когда пользователь изменил:

·         zoom;

·         страницу;

·         page box;

·         файл;

·         Overprint Preview;

·         layer state;

старый результат должен считаться устаревшим.

if (response.requestId !== latestRequestId) {
  discardResponse(response);
  return;
}

Даже если низкоуровневый MuPDF render невозможно прервать посередине, приложение не должно показывать устаревший результат.

Для зависшего или патологического файла:

1.      срабатывает watchdog;

2.      Worker завершается;

3.      временные результаты удаляются;

4.      создаётся новый Worker;

5.      пользователь получает понятную ошибку.

19. Безопасность

PDF и AI считать недоверенными входными данными.

Необходимо:

·         ограничить размер файла;

·         ограничить максимальное число страниц;

·         ограничить итоговые pixel dimensions;

·         выполнять parsing только в Worker;

·         использовать watchdog;

·         обрабатывать corrupted PDF;

·         обрабатывать encrypted PDF;

·         не выполнять document JavaScript;

·         не запускать embedded actions;

·         не открывать автоматически внешние URL;

·         не извлекать и не запускать embedded files;

·         не логировать содержимое confidential artwork;

·         обновлять MuPDF только после security review и regression tests.

Для password-protected PDF MuPDF предоставляет needsPassword() и authenticatePassword().

23. Эталонное сравнение

Каждый тест открыть:

1.      В Adobe Illustrator с включённым Overprint Preview.

2.      В Adobe Acrobat Pro Output Preview с Simulate Overprinting.

3.      В приложении через MuPDF.js.

Использовать одинаковые:

·         page box;

·         output intent;

·         zoom;

·         фон страницы;

·         layer visibility.

Не требовать полного pixel-perfect совпадения всей страницы: anti-aliasing разных движков может немного отличаться.

Проверять:

·         поведение критических областей;

·         сохранение или knockout нижнего цвета;

·         исчезновение white overprint;

·         правильность прозрачности;

·         отсутствие посторонних RGB halos;

·         поведение spot colors;

·         границы clipping masks.

Для расширенного тестирования использовать Ghent PDF Output Suite 5.0. Он создан для проверки PDF-workflow в graphic arts и содержит тестовые patches для CMYK, spot colors, ICC, transparency и overprint.

24. Критерии приёмки

Функция считается реализованной только при выполнении всех условий.

Functional

·         PDF импортируется.

·         PDF-compatible AI импортируется.

·         AI без PDF representation корректно отклоняется.

·         Все страницы документа доступны.

·         Page box можно выбрать.

·         Artwork масштабируется и перемещается.

·         Original File остаётся неизменным.

·         Preview не используется как источник финального PDF.

Overprint

·         black overprint соответствует Adobe;

·         black knockout соответствует Adobe;

·         white overprint соответствует Adobe;

·         OPM 0/1 проходит тест;

·         spot overprint проходит тест;

·         DeviceN проходит тест;

·         transparency + spot проходит тест;

·         PDF/X-1a и PDF/X-4 проходят обязательные сценарии.

Performance

·         интерфейс не блокируется во время render;

·         stale render не появляется на экране;

·         zoom работает плавно на существующем bitmap;

·         high-resolution render появляется после завершения zoom;

·         большие страницы переходят на tiling;

·         приложение восстанавливается после Worker timeout.

Memory

·         все MuPDF objects уничтожаются;

·         повторные открытия не вызывают линейного роста памяти;

·         cache ограничен;

·         ImageBitmap закрывается при удалении;

·         Worker может быть полностью перезапущен.

Licensing

MuPDF распространяется по AGPL либо по коммерческой лицензии. Для закрытого корпоративного или коммерческого приложения вопрос лицензирования должен быть решён до production deployment.

27. Итоговое техническое решение

Для первого production-capable варианта использовать:

Official mupdf npm package
+ WebAssembly
+ dedicated Web Worker
+ PDFPage.toPixmap
+ DeviceRGB output
+ usage = Print
+ selectable page box
+ progressive raster rendering
+ tiled rendering for large pages
+ strict WASM memory management
+ immutable original PDF/AI storage

Перед полной разработкой обязательно подтвердить overprint behaviour стандартной WASM-сборки.

Главная контрольная развилка:

Stock MuPDF.js passes Adobe reference tests
        │
        ├── Yes → use stock package
        │
        └── No / explicit toggle required
                 ↓
             custom WASM wrapper
             exposing MuPDF Core
             overprint modes 0/1/2

Без этого Capability Spike невозможно честно гарантировать, что стандартный публичный JavaScript API отображает каждый PDF точно в требуемом режиме Overprint Preview.

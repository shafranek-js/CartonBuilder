Концепция развития приложения

Размещение artwork на развёртке коробки

Анализ задачи, выявленные требования, неоднозначности, риски реализации и рекомендуемый план выполнения.

Цель

Следующий этап проекта — превратить конструктор развёртки в простой редактор размещения artwork: пользователь создаёт геометрию коробки, загружает готовое изображение и визуально совмещает его с панелями развёртки.

Какую реальную проблему вы пытаетесь решить

Пользователю нужно понять, как готовое изображение будет расположено на плоской развёртке упаковки, не используя профессиональные программы вроде Illustrator, ArtPro+ или CAD-систем.

Фактически приложение решает задачу визуального монтажа:

Развёртка коробки
        +
Artwork / изображение
        ↓
Совмещённый макет

Пользователь должен иметь возможность:

  • построить нужную конфигурацию коробки;
  • загрузить artwork;
  • положить artwork под контуры развёртки;
  • подобрать его размер;
  • переместить его относительно панелей;
  • увидеть, какие части изображения попадут на Front, Base и остальные панели;
  • подготовить результат для дальнейшего использования или проверки.

Для упаковочного процесса это может быть полезно как:

  • быстрый инструмент предварительной компоновки;
  • визуальная проверка размещения дизайна;
  • средство объяснения конструкции дизайнеру или заказчику;
  • упрощённый mockup до передачи в профессиональную prepress-систему.

При этом первая версия ещё не будет полноценным production-ready artwork editor, если в ней нет управления цветом, bleed, trapping, overprint, spot colors, шрифтов и технических допусков.

Что уже понятно

1. Переход к следующему этапу

После того как пользователь разместил все шесть панелей:

  • счётчик показывает 6/6;
  • кнопка Continue становится активной;
  • пользователь нажимает Continue;
  • приложение переходит в режим размещения изображения.

Вероятнее всего, геометрия развёртки после этого остаётся неизменной или блокируется от случайного редактирования.

2. Загрузка файла

Пользователь может загрузить:

  • PNG;
  • JPG/JPEG;
  • PDF.

Должны поддерживаться два способа:

Через стандартный выбор файла

  • кнопка Upload image, Choose file или аналогичная;
  • открывается системный проводник;
  • пользователь выбирает файл.

Через drag-and-drop

  • пользователь перетаскивает файл на рабочую область;
  • зона загрузки визуально реагирует на наведение файла;
  • после отпускания файл загружается.

3. Положение изображения в слоях

Изображение размещается под развёрткой.

Предполагаемый порядок слоёв:

Верхний слой:    контуры и подписи развёртки
Средний слой:    загруженное изображение
Нижний слой:     фон рабочего полотна

Это означает:

  • контуры панелей всегда видны;
  • линии между панелями остаются поверх artwork;
  • Front Panel и Base Panel можно идентифицировать даже после загрузки изображения;
  • пользователь перемещает artwork, не перемещая саму развёртку.

Внутренняя цветная заливка панелей, вероятно, должна стать прозрачной или полупрозрачной, иначе изображение под ней будет плохо видно.

4. Масштабирование изображения

Изображение можно:

  • увеличивать;
  • уменьшать;
  • сохранять исходные пропорции.

То есть отношение ширины к высоте не должно изменяться.

Например:

scale = 100%
scale = 125%
scale = 75%

Возможные способы управления:

  • маркеры по углам рамки;
  • ползунок масштаба;
  • поле с процентом;
  • кнопки + и −;
  • колесо мыши при зажатой клавише-модификаторе.

Для первой версии лучше сочетать:

  • угловые маркеры для визуального изменения;
  • числовое значение масштаба в процентах;
  • кнопку Reset size.

5. Перемещение изображения

Пользователь должен иметь возможность:

  • нажать на изображение;
  • удерживать кнопку мыши;
  • перемещать изображение по полотну;
  • отпустить его в нужной позиции.

На touch-устройствах аналогичное действие выполняется пальцем, хотя desktop по-прежнему может быть приоритетной платформой.

6. Развёртка остаётся ориентиром

Развёртка используется как неподвижный шаблон:

  • линии панелей не двигаются при перетаскивании artwork;
  • размеры панелей не меняются;
  • изображение подстраивается под развёртку, а не наоборот.

Это принципиальное разделение:

Canvas navigation — перемещение вида
Artwork transform — перемещение изображения
Dieline geometry — неизменяемая конструкция

Где есть неоднозначности

1. Что именно загружает пользователь

Есть как минимум три возможных сценария.

Сценарий A: единое изображение всей развёртки

Пользователь загружает один большой artwork-файл, уже содержащий дизайн всех панелей.

Тогда приложение помогает совместить его с выбранной геометрией.

Сценарий B: изображение только для лицевой панели

Пользователь загружает отдельную картинку, например дизайн Front Panel, и хочет разместить её на одной панели.

Сценарий C: обычное фоновое изображение

Пользователь загружает фотографию или иллюстрацию и растягивает её через несколько панелей.

По текущему описанию наиболее вероятен сценарий A или C: одно изображение свободно располагается под всей развёрткой.

Это нужно явно зафиксировать, поскольку при сценарии B потребуется:

  • выбор целевой панели;
  • автоматическая обрезка;
  • отдельные изображения для разных панелей;
  • управление каждой панелью независимо.

2. Должно ли изображение обрезаться по форме развёртки

Возможны два режима.

Полное изображение видно на всём холсте

Artwork отображается и внутри, и снаружи панелей.

Плюсы:

  • легко перемещать;
  • пользователь видит весь исходный файл;
  • проще реализовать.

Минус:

  • результат выглядит менее чисто.

Изображение видно только внутри панелей

Развёртка работает как маска, а всё за пределами шести панелей скрывается.

Плюсы:

  • наглядно видно будущую упаковку;
  • результат выглядит аккуратно.

Минусы:

  • пользователю труднее понимать, какая часть изображения находится за границами;
  • при настройке позиции полезно временно видеть скрытые части.

Рекомендую два режима:

  • Edit mode — artwork виден целиком, области вне развёртки приглушены;
  • Preview mode — artwork обрезан по форме развёртки.

3. Как обрабатывать PDF

PDF существенно отличается от PNG и JPG.

Нужно решить:

  • поддерживается только первая страница;
  • пользователь выбирает страницу;
  • многостраничный PDF запрещён;
  • PDF растеризуется для отображения;
  • сохраняется ли исходная векторная структура;
  • какой DPI используется при рендеринге.

Для MVP разумное правило:

  • принять PDF;
  • если в нём одна страница — загрузить её;
  • если страниц несколько — показать выбор страницы;
  • для редактора создать preview-изображение;
  • сохранить оригинальный PDF в состоянии проекта для возможного дальнейшего экспорта.

Важно: если просто преобразовать PDF в картинку низкого разрешения, итог может выглядеть хорошо на экране, но быть непригодным для печати.

4. Что означает «увеличивать и уменьшать»

Может быть перепутано два разных действия:

Масштаб artwork

Меняется физический размер загруженного изображения относительно развёртки.

Например, логотип становится больше относительно Front Panel.

Zoom рабочего полотна

Меняется только экранное увеличение всего документа:

  • artwork;
  • развёртки;
  • линий;
  • интерфейса.

Геометрические отношения при этом не меняются.

Оба механизма нужны, но они должны быть визуально и функционально разделены.

5. В каких единицах хранится размер изображения

Развёртка построена в миллиметрах, а PNG и JPG имеют:

  • ширину и высоту в пикселях;
  • иногда DPI;
  • иногда DPI отсутствует или недостоверен.

Например, изображение 3000 × 2000 px без DPI не имеет однозначного физического размера в миллиметрах.

Нужно выбрать правило начального размещения.

Варианты:

  • интерпретировать DPI из файла;
  • использовать 96 DPI;
  • автоматически вписать изображение в bounding box развёртки;
  • попросить пользователя указать физическую ширину;
  • масштабировать изображение относительно Front Panel.

Для простого визуального редактора лучше:

  1. загрузить изображение;
  2. автоматически вписать его в общую область развёртки;
  3. показать текущий масштаб в процентах;
  4. позднее добавить возможность задавать ширину в миллиметрах.

6. От какой точки масштабируется изображение

При изменении размера изображение может масштабироваться:

  • относительно центра;
  • относительно противоположного угла;
  • относительно верхнего левого угла;
  • относительно выбранной anchor point.

Для привычного редактора:

  • перетаскивание углового маркера фиксирует противоположный угол;
  • изменение масштаба через поле процентов масштабирует от центра.

7. Разрешено ли вращение

Вы указали перемещение и пропорциональное масштабирование, но не вращение.

Вращение может быть полезно, особенно когда:

  • PDF или изображение загружено в неправильной ориентации;
  • artwork нужно развернуть на 90°;
  • конструкция коробки расположена вертикально, а artwork горизонтально.

Для MVP можно ограничиться кнопками:

  • Rotate 90° clockwise;
  • Rotate 90° counterclockwise.

Свободное вращение на произвольный угол, вероятно, не требуется на первом этапе.

8. Можно ли загрузить несколько изображений

Неясно, будет ли поддерживаться:

  • только один artwork;
  • несколько изображений;
  • логотип поверх фона;
  • отдельный artwork для каждой панели.

По вашему описанию сейчас речь идёт об одном загруженном изображении.

Это стоит оставить ограничением MVP. Кнопка повторной загрузки заменяет предыдущий artwork.

9. Что происходит с цветами Front и Base

Сейчас:

  • Front Panel голубая;
  • Base Panel розовая;
  • остальные панели белые.

После размещения artwork непрозрачные заливки закроют изображение.

Варианты:

  • убрать заливки полностью;
  • оставить их с прозрачностью 10–20%;
  • показывать цвет только по рамке;
  • использовать заливки только при выключенном artwork.

Рекомендация:

  • Front и Base обозначать цветной рамкой и подписью;
  • заливку делать почти прозрачной;
  • в Preview mode скрывать цветные заливки полностью.

10. Должны ли отображаться названия панелей поверх artwork

Нужно решить, остаются ли надписи:

  • Front Panel;
  • Base Panel;
  • названия остальных панелей.

Для редактирования они полезны. Для финального preview или экспорта — могут мешать.

Логично добавить переключатели:

  • Show panel names;
  • Show dieline;
  • Show artwork only;
  • Preview.

11. Что делать с частью изображения вне развёртки

Необходимо определить:

  • разрешать свободный выход за границы;
  • запрещать полностью вывести artwork за пределы;
  • автоматически возвращать изображение;
  • показывать предупреждение.

Лучше разрешить свободное перемещение. Иногда пользователь намеренно должен вывести большую часть изображения за пределы развёртки, чтобы выбрать нужный фрагмент.

12. Что происходит после завершения совмещения

Пока не определено, что является результатом второго этапа.

Возможные действия:

  • сохранить проект;
  • экспортировать PNG;
  • экспортировать SVG;
  • экспортировать PDF;
  • скачать изображение с линиями развёртки;
  • скачать artwork, обрезанный по панелям;
  • перейти к 3D-preview коробки;
  • продолжить редактирование отдельных панелей.

От этого зависит архитектура хранения исходного artwork и качество его обработки.

Что можно неправильно понять, если сразу начать писать код

1. Реализовать zoom вместо изменения размера artwork

Колесо мыши может визуально увеличить картинку, но фактический размер относительно коробки не изменится. Пользователь будет считать, что масштабирует artwork, хотя на самом деле просто увеличивает экран.

Нужны два разных состояния:

canvasZoom
artworkScale

2. Вставить изображение поверх линий развёртки

Тогда artwork закроет:

  • границы панелей;
  • названия;
  • конструктивные линии.

Правильный порядок слоёв должен быть задан явно.

3. Скрыть изображение цветной заливкой панелей

Если сохранить текущую непрозрачную голубую и розовую заливку, artwork под Front и Base станет частично или полностью невидим.

4. Потерять качество загруженного PDF

Можно отрисовать PDF в низком разрешении и затем использовать эту растровую копию при экспорте. На экране это будет выглядеть приемлемо, но для упаковочного artwork результат окажется непригодным.

Preview и финальный исходник нужно рассматривать отдельно.

5. Использовать пиксели как физические миллиметры

Развёртка существует в миллиметровой системе, а изображение — в пикселях. Неправильное смешение этих систем приведёт к непредсказуемому масштабу.

6. Автоматически обрезать изображение без возможности увидеть оригинал

Пользователь может не понимать, куда исчезла часть artwork и как её вернуть. Во время редактирования лучше сохранять видимость или хотя бы контур полной границы изображения.

7. Сделать resize-маркеры, искажающие пропорции

Если боковые маркеры меняют ширину независимо от высоты, пользователь сможет случайно растянуть artwork.

На первом этапе безопаснее разрешить resize только через углы и всегда сохранять aspect ratio.

8. Перемещать развёртку вместо artwork

Когда пользователь нажимает внутри панели, система должна понимать текущий режим. Иначе попытка подвинуть картинку может сдвинуть весь canvas или dieline.

9. Не учесть прозрачность PNG

PNG может содержать alpha channel. Его нельзя автоматически заменять белым фоном, иначе логотипы и вырезанные объекты будут отображаться неправильно.

10. Обработать PDF как обычное изображение

Браузерный <img> не поддерживает PDF как PNG или JPG. Для PDF потребуется отдельная логика рендеринга страниц.

11. Заблокировать изменение развёртки навсегда

После Continue пользователь может заметить, что выбрал неудобную конфигурацию панелей.

Нужна возможность:

  • вернуться к конструкции;
  • изменить развёртку;
  • сохранить или восстановить позицию artwork, если это возможно.

Состояние до загрузки

В центре холста отображается drop zone:

Drop PNG, JPG or PDF here
or
[Choose file]

Также указываются:

  • поддерживаемые форматы;
  • максимальный размер файла;
  • правило для многостраничного PDF.

Состояние после загрузки

  • artwork автоматически размещается под развёрткой;
  • изображение выделено рамкой;
  • по углам показаны resize handles;
  • пользователь может двигать изображение;
  • в боковой панели показываются:
    • имя файла;
    • исходный размер в пикселях;
    • размер файла;
    • масштаб;
    • позиция X/Y;
    • угол поворота.

Предлагаемые правила MVP

Загрузка

  • один файл одновременно;
  • PNG, JPG, JPEG, PDF;
  • выбор через проводник или drag-and-drop;
  • новая загрузка заменяет текущую после подтверждения;
  • PNG-прозрачность сохраняется;
  • для PDF используется выбранная страница.

Начальное размещение

После загрузки:

  • artwork центрируется относительно bounding box развёртки;
  • автоматически масштабируется так, чтобы полностью покрыть или вписаться в развёртку;
  • пользователь может выбрать:
    • Fit inside;
    • Fill dieline.

Для первой версии рекомендую Fit inside как безопасный default.

Управление artwork

  • drag для перемещения;
  • четыре угловых resize handle;
  • пропорции всегда заблокированы;
  • поле масштаба в процентах;
  • кнопки − и + для масштаба;
  • Reset transform;
  • Center artwork;
  • Rotate left/right на 90°.

Управление canvas

  • колесо мыши — zoom canvas;
  • drag средней кнопкой или Space + drag — pan canvas;
  • Fit to screen;
  • 100% view.

Это управление должно быть визуально отделено от трансформации artwork.

Отображение развёртки

  • artwork находится ниже;
  • контуры панелей находятся выше;
  • названия панелей можно включать и выключать;
  • Front и Base имеют цветной контур;
  • внутренние заливки прозрачны;
  • активное изображение имеет рамку и handles.

Режим Preview

В Preview mode:

  • handles скрываются;
  • названия панелей можно скрыть;
  • artwork обрезается по форме развёртки;
  • область вне развёртки становится белой или прозрачной;
  • остаются только нужные конструктивные линии.

Предлагаемая модель состояний

BOX_EDITING
    ↓ Continue

    ↓ Upload

    ↓ Preview

    ↓ Back to edit

ARTWORK_EDITING

Изменение геометрии развёртки может изменить положение artwork.

План выполнения

Этап 1. Зафиксировать продуктовые правила

До проектирования нужно принять решения по следующим вопросам:

  1. Один artwork или несколько.
  2. Artwork для всей развёртки или отдельных панелей.
  3. Как отображается область вне развёртки.
  4. Нужно ли вращение.
  5. Как обрабатываются многостраничные PDF.
  6. Что является итоговым результатом.
  7. Нужно ли физическое соответствие миллиметрам и DPI.
  8. Можно ли вернуться к редактированию коробки.

Результат: однозначный UX flow второго этапа.

Этап 2. Спроектировать экран размещения artwork

Подготовить макет состояний:

  • до загрузки;
  • drag-over;
  • загрузка файла;
  • успешная загрузка;
  • ошибка;
  • редактирование;
  • preview;
  • замена файла;
  • возврат к конструкции.

Особое внимание уделить разделению:

  • canvas zoom;
  • artwork scale;
  • dieline layer;
  • artwork layer.

Этап 3. Определить координатную систему

Вся сцена должна использовать одну логическую систему координат, желательно миллиметры модели.

Необходимо определить преобразования:

Исходные пиксели изображения
        ↓
Физический или логический размер artwork
        ↓
Позиция и масштаб в координатах развёртки
        ↓
Экранное отображение с canvas zoom

Основные параметры artwork:

x
y
scale
rotation
sourceWidth
sourceHeight
aspectRatio

Параметры canvas:

viewportX
viewportY
zoom

Эти группы нельзя смешивать.

Этап 4. Реализовать загрузочный workflow

Функционально потребуется:

  • file picker;
  • drag-and-drop;
  • проверка MIME type;
  • проверка расширения;
  • ограничение размера;
  • обработка ошибок;
  • чтение PNG/JPG;
  • отдельный pipeline для PDF;
  • создание preview;
  • сохранение исходного файла в состоянии проекта.

Этап 5. Реализовать слои сцены

Рекомендуемый порядок:

1. Canvas background
2. Full artwork image
3. Outside-area dimming or mask
4. Panel fills
5. Panel borders
6. Panel labels
7. Artwork selection frame
8. Resize handles
9. UI overlays

В Preview mode порядок и видимость некоторых слоёв меняются.

Этап 6. Реализовать трансформации artwork

Добавить:

  • selection;
  • drag;
  • proportional resize;
  • scale percentage;
  • center;
  • reset;
  • optional 90° rotation;
  • keyboard nudging.

Полезные клавиши:

  • стрелки — перемещение на небольшой шаг;
  • Shift + стрелки — крупный шаг;
  • Delete — удалить artwork после подтверждения;
  • Escape — снять выделение;
  • 0 — fit to screen.

Этап 7. Добавить Preview mode

Preview должен отвечать на главный вопрос:

Как artwork фактически распределяется по панелям коробки?

В этом режиме нужно:

  • скрыть редакторские handles;
  • применить маску развёртки;
  • оставить dieline видимым;
  • позволить переключать подписи;
  • показать Front и Base без перекрытия artwork.

Этап 8. Определить сохранение проекта

Проект должен сохранять как минимум:

{
  "box": {
    "width": 150,
    "height": 90,
    "depth": 40,
    "panels": []
  },
  "artwork": {
    "fileName": "design.pdf",
    "page": 1,
    "x": 12.5,
    "y": -8,
    "scale": 1.25,
    "rotation": 0
  },
  "view": {
    "zoom": 1,
    "panX": 0,
    "panY": 0
  }
}

Нужно решить, хранится ли сам файл внутри проекта или только ссылка/идентификатор.

Этап 9. Спроектировать экспорт

Минимальный полезный набор:

  • PNG preview;
  • PDF preview;
  • SVG с dieline и raster artwork;
  • JSON проекта.

Для профессионального применения позднее могут понадобиться:

  • PDF с сохранением исходного качества;
  • отдельный dieline layer;
  • spot color для линии высечки;
  • bleed;
  • crop marks;
  • scale 1:1;
  • профиль цвета;
  • предупреждение о низком разрешении.

Этап 10. Провести пользовательскую проверку

Нужно протестировать минимум такие сценарии:

  1. PNG с прозрачностью.
  2. Большой JPG.
  3. Одностраничный PDF.
  4. Многостраничный PDF.
  5. Очень широкое изображение.
  6. Очень высокое изображение.
  7. Artwork меньше Front Panel.
  8. Artwork больше всей развёртки.
  9. Перемещение за пределы canvas.
  10. Масштабирование до очень малого и очень большого значения.
  11. Возврат к редактированию коробки.
  12. Замена уже загруженного файла.
  13. Preview и возврат к редактированию.
  14. Экспорт без потери исходных пропорций.

Рекомендуемый объём второй версии

Для первого рабочего релиза этапа artwork достаточно:

  1. переход по Continue;
  2. загрузка одного PNG, JPG или одностраничного PDF;
  3. drag-and-drop;
  4. автоматическое центрирование;
  5. перемещение artwork;
  6. пропорциональное масштабирование через углы;
  7. scale в процентах;
  8. поворот на 90°;
  9. Reset и Center;
  10. развёртка поверх artwork;
  11. прозрачные заливки панелей;
  12. режим Preview с маской;
  13. замена или удаление изображения;
  14. возврат к редактированию коробки;
  15. экспорт preview в PNG.

Главный принцип архитектуры: не превращать изображение и развёртку в один плоский bitmap. Развёртка, artwork и viewport должны оставаться отдельными объектами. Тогда позднее можно будет добавить panel-specific artwork, bleed, технические линии, 3D-preview и качественный PDF-экспорт без полной переработки приложения.

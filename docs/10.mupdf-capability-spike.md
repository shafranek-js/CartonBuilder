# MuPDF.js Overprint Capability Spike

Status: Historical/Research (decision record)
Owner: maintainer `src/artwork`, `src/pdf-renderer`
Last verified: 2026-08-06
Canonical for: решение о stock mupdf vs custom WASM wrapper для Overprint Preview

## Цель

ТЗ «Техническое задание по внедрению MuPDF.js для PDF-AI Overprint Preview»
(§2, §27) требует до основной разработки ответить на развилку: поддерживает ли
стандартный npm-пакет `mupdf` (MuPDF.js) overprint simulation, сопоставимую с
Adobe, или нужен custom WASM wrapper.

## Выводы

### 1. Stock MuPDF.js НЕ симулирует overprint

`PDFPage.toPixmap` композитит все объекты с knockout (source-over). Флаги
`/OP`, `/op`, `/OPM` из ExtGState читаются, но не влияют на композитинг.
`enableICC()` результата не меняет.

Доказательства:
- Test 03 (белый overprint): левый прямоугольник `0 0 0 0 k` с overprint fill
  отрисован БЕЛЫМ, а не невидимым → фон выбит.
- Test 04: OPM 0 и OPM 1 дают идентичный цвет.
- Test 01: 50% K с overprint даёт серый (knockout), а не тёмно-красный.

### 2. JS API не предоставляет управления overprint/separations

В `mupdf.d.ts` и WASM-склейке отсутствуют: параметры цвета, separations,
`fz_page_uses_overprint`, output intent. Единственный путь рендера —
`toPixmap(matrix, colorspace, alpha, showExtras, usage, box)`.

### 3. Механизм overprint simulation в mupdf известен (из исходников C)

В `source/tools/mudraw.c` (`drawpage`):
```
if (spots != SPOTS_NONE) {
    seps = fz_page_separations(page);
    ...
    else if (fz_page_uses_overprint(page))
        seps = fz_new_separations(ctx, 0);   // пустой seps FORCES overprint on
}
```
Overprint simulation (mutool `-M 1`, по умолчанию) включается, когда pixmap
создан с объектом `fz_separations` (пустым — для симуляции, либо с реальными
spott'ами `FZ_SEPARATION_SPOT` — для полноценного spot rendering, `-M 2`).
JS `toPixmap` создаёт pixmap без separations → режим 0 (без overprint).

## Решение (главная развилка §27)

**Stock MuPDF.js НЕ проходит Adobe-референсы по overprint** (подтверждено
сравнением probe-пикселей: тесты 01, 03, 09, 11) → для выполнения ТЗ необходим
**custom WASM wrapper** (этап 4), который:

1. рендерит страницу в pixmap, созданный с `fz_separations` (пустым — режим 1,
   с реальными спотами — режим 2), по логике mudraw `-M`;
2. добавляет JS-API `setOverprintRenderingMode(0 | 1 | 2)` / отдаёт pixmap с seps;
3. по возможности — `fz_page_uses_overprint` и separations metadata для панели
   сепараций (этап 5).

Следствие для плана:
- Этапы 1–3 (базовый рендерер, production rendering, tiled) строятся на stock
  `mupdf` — open/render/pagebox/layers/CMYK/spot/DeviceN/transparency работают.
- Overprint Preview (режим 1) и панель сепараций (режим 2) требуют custom WASM.
- До custom WASM показывать read-only статус: overprint simulation недоступна.

## Дополнительные находки

- `mupdf.Document.recognizeContent` в 1.28.0 НЕТ. Определение PDF/AI:
  `Document.openDocument(bytes, "application/pdf")` + `isPDF()`; не-PDF →
  throw ("no objects found").
- Type 4 (PostScript calculator) функции в mupdf обязаны начинаться с `{ ... }`
  (`pdf_load_calc_function` требует токен OPEN_BRACE).
- PDF/X OutputIntent: mupdf читает профиль, но при несоответствии выводит warn
  «invalid ICC colorspace» и фолбэчит на DeviceCMYK; рендер не ломается.
- Separation/DeviceN/transparency groups рендерятся корректно.

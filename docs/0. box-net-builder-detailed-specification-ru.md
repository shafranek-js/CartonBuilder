## Box Net Builder / Create Basic Box

**Версия спецификации:** 1.0  
**Дата:** 30 июля 2026 г.  
**Статус:** спецификация текущего рабочего прототипа

**Назначение документа:** дать разработчику, тестировщику, архитектору или интегратору полное понимание поведения приложения без необходимости предварительно изучать исходный код.

# 1. Краткое описание системы

Box Net Builder — автономное браузерное HTML/CSS/JavaScript-приложение для интерактивного построения плоской развёртки прямоугольной коробки из шести основных панелей.

Пользователь задаёт три физических размера коробки:

- `Width` — ширина;
- `Height` — высота;
- `Depth` — глубина.

После ввода размеров приложение автоматически создаёт лицевую панель `Front Panel`. Пользователь последовательно добавляет остальные физические грани коробки, нажимая кнопки `+`, расположенные возле допустимых свободных рёбер уже созданных панелей.

Приложение самостоятельно:

- определяет, какая физическая грань коробки будет создана при сгибе через выбранное ребро;
- вычисляет размер и ориентацию новой панели;
- не позволяет добавить одну и ту же физическую грань дважды;
- не позволяет создать перекрывающиеся панели;
- показывает кнопку удаления только для конечных панелей, не имеющих дочерних панелей;
- считает количество размещённых граней;
- активирует кнопку `Continue` только после размещения всех шести граней;
- экспортирует завершённую развёртку в SVG с физическими размерами в миллиметрах.

Приложение не является промышленным CAD-редактором высечки. Оно создаёт геометрическую структуру из шести прямоугольных граней без клапанов, линий реза, биговок, припусков, bleed и компенсации толщины материала.

# 2. Решаемая бизнес-задача

## 2.1. Основная проблема

Пользователю необходимо быстро и визуально сформировать корректную плоскую компоновку граней прямоугольной коробки, не рассчитывая вручную:

- размеры каждой отдельной панели;
- взаимное положение панелей;
- ориентацию панели при присоединении к разным сторонам;
- повторное использование уже добавленной физической грани;
- геометрические пересечения.

## 2.2. Практическое назначение

Приложение может использоваться как:

- первый этап конструктора упаковки;
- средство выбора базовой структуры развёртки;
- прототип UI для artwork management system;
- источник SVG-геометрии для дальнейшего добавления artwork;
- учебный или демонстрационный инструмент;
- front-end компонент более крупной системы создания упаковки.

## 2.3. Ценность для пользователя

Пользователь работает не с абстрактными прямоугольниками, а с физическими гранями коробки. Система гарантирует, что в модели одновременно существует не более одной грани каждого типа:

1. Front;
2. Back;
3. Top;
4. Bottom / Base;
5. Left;
6. Right.

# 3. Область действия

## 3.1. Входит в текущую версию

- ввод трёх размеров коробки в миллиметрах;
- автоматическое создание Front Panel;
- построение развёртки до шести панелей;
- добавление панелей через допустимые рёбра;
- трёхмерная логика ориентации при двумерном отображении;
- предотвращение дубликатов физических граней;
- предотвращение геометрического наложения;
- удаление конечных панелей;
- автоматическое масштабирование и центрирование;
- визуальное выделение Front Panel и Base Panel;
- индикатор `Placed panels: X/6`;
- блокировка `Continue` до завершения;
- итоговый диалог;
- экспорт SVG;
- JS API для интеграции и автоматизированных тестов;
- события завершения и отмены.

## 3.2. Не входит в текущую версию

- клеевой клапан;

- линии реза и биговки как разные типы линий;
- материал, толщина картона и радиусы сгиба;
- компенсация толщины материала;
- допуски;
- bleed, safe area и trim area;
- размещение текста, изображений, штрихкодов или artwork;
- 3D-превью собранной коробки;
- ручное перемещение отдельной панели;
- ручное вращение панели;
- произвольный многоугольный контур;
- сохранение проекта в localStorage или на сервер;
- загрузка ранее сохранённого проекта;
- экспорт PDF, DXF, CF2, ARD или других CAD-форматов;
- серверная часть;
- аутентификация;
- управление версиями проекта;
- локализация интерфейса;
- undo/redo;
- клавиатурные команды удаления панели;
- ручной zoom/pan пользователем.

# 4. Термины и определения

| Термин | Определение |
|---|---|
| Box net | Плоская развёртка коробки, состоящая из соединённых панелей. |
| Panel | Прямоугольная двумерная проекция одной физической грани коробки. |
| Face | Физическая грань трёхмерной коробки: front, back, top, bottom, left или right. |
| Front Panel | Начальная лицевая грань, создаваемая автоматически. |
| Base Panel | Нижняя физическая грань коробки; в коде имеет ключ `bottom`. |
| Edge | Одно из четырёх рёбер двумерной панели: `top`, `right`, `bottom`, `left`. |
| Parent panel | Панель, к ребру которой была присоединена новая панель. |
| Child panel | Панель, созданная через ребро родительской панели. |
| Leaf panel | Панель, не имеющая дочерних панелей. Только такая панель может быть удалена. |
| Basis | Тройка ортогональных 3D-векторов панели: `normal`, `up`, `right`. |
| Normal | Вектор, определяющий физическую сторону коробки. |
| Eligible edge | Свободное ребро, через которое можно создать ещё не использованную грань без пересечения. |
| Potential | Расчётный результат возможного добавления панели до фактического изменения модели. |
| Workspace | SVG-холст, на котором отображается развёртка. |
| Complete state | Состояние, в котором размещены все 6 панелей. |

# 5. Пользовательские роли

Текущая версия предполагает одну роль — **обычный пользователь конструктора**.

Пользователь имеет право:

- изменять размеры;
- добавлять панели;
- удалять допустимые панели;
- сбрасывать развёртку;
- завершать построение;
- экспортировать SVG.

Разделения на администратора, автора, ревьюера или утверждающего в текущей версии нет.

# 6. Основной пользовательский сценарий

## 6.1. Стартовое состояние

При открытии приложения:

- отображаются размеры по умолчанию:
  - Width = `150 mm`;
  - Height = `90 mm`;
  - Depth = `40 mm`;
- создаётся одна Front Panel размером `150 × 90 mm`;
- счётчик показывает `1/6`;
- `Continue` отключена;
- `Cancel` активна;
- у Front Panel доступны четыре потенциальных направления добавления.

## 6.2. Последовательность, соответствующая референсным экранам

1. Пользователь нажимает `+` снизу Front Panel.
2. Создаётся Base Panel размером `Width × Depth`, то есть `150 × 40 mm`.
3. Пользователь нажимает `+` сверху Front Panel.
4. Создаётся Top Panel размером `Width × Depth`, то есть `150 × 40 mm`.
5. Пользователь нажимает `+` сверху Top Panel.
6. Создаётся Back Panel размером `Width × Height`, то есть `150 × 90 mm`.
7. Пользователь нажимает `+` слева от Front Panel.
8. Создаётся Left Panel размером `Depth × Height`, то есть `40 × 90 mm`.
9. Пользователь нажимает `+` справа от Back Panel.
10. Создаётся Right Panel размером `Depth × Height`, то есть `40 × 90 mm`.
11. Счётчик показывает `6/6`.
12. Все кнопки `+` исчезают, потому что каждая физическая грань уже использована.
13. `Continue` становится активной.
14. Нажатие `Continue` открывает итоговый диалог.
15. Пользователь может вернуться к редактированию или экспортировать SVG.

## 6.3. Альтернативные последовательности

Приложение не жёстко привязано к указанной последовательности. Пользователь может присоединять грани в другом порядке, если одновременно выполняются условия:

- результирующая физическая грань ещё не существует;
- целевое ребро свободно;
- новая панель не пересекает существующие панели.

Например, Base Panel может быть создана не первой, а позже. При этом физическая грань `bottom` всё равно автоматически получит имя `Base Panel` и специальный цвет.

# 7. Функциональные требования

## FR-001. Инициализация приложения

При первой загрузке приложение должно:

1. создать объект модели с размерами `150 × 90 × 40 mm`;
2. создать Front Panel;
3. отрисовать рабочую область;
4. установить счётчик `1/6`;
5. отключить кнопку `Continue`;
6. зарегистрировать обработчики событий UI;
7. зарегистрировать `ResizeObserver` для рабочей области либо fallback на событие `resize`;
8. предоставить глобальный объект `window.boxNetApp`.

## FR-002. Ввод размеров

Пользователь должен иметь возможность ввести:

- Width;
- Height;
- Depth.

Каждое поле:

- имеет HTML-тип `number`;
- имеет `min="0.1"`;
- имеет `step="0.1"`;
- использует `inputmode="decimal"`;
- визуально показывает суффикс `mm`;
- применяет значение при событии `change`;
- при нажатии Enter снимает фокус, что вызывает применение значения.

## FR-003. Валидация размеров

Размер считается допустимым, если:

- преобразуется в число;
- является конечным числом;
- больше нуля;
- не превышает `100000`.

При ошибке:

- модель не изменяется;
- поле возвращается к последнему принятому значению;
- показывается toast с сообщением об ошибке.

Текущие сообщения модели:

- `<name> must be a positive number.`;
- `<name> is too large.`.

## FR-004. Изменение размеров при наличии дополнительных панелей

Если размещена только Front Panel:

- размеры применяются без подтверждения;
- модель пересоздаётся.

Если размещено более одной панели:

- приложение должно показать системный `window.confirm`;
- текст: `Changing the box dimensions will reset the current panel layout. Continue?`;
- при подтверждении развёртка сбрасывается до Front Panel с новыми размерами;
- при отказе поля возвращаются к прежним значениям.

## FR-005. Автоматическое создание Front Panel

Front Panel создаётся при каждом `reset()`.

Свойства:

- `id = "front"`;
- `faceKey = "front"`;
- `faceName = "Front Panel"`;
- `normal = [0, 0, 1]`;
- `up = [0, 1, 0]`;
- `right = [1, 0, 0]`;
- `x = 0`;
- `y = 0`;
- `width = dimensions.width`;
- `height = dimensions.height`;
- `parentId = null`;
- `parentEdge = null`;
- не может быть удалена.

## FR-006. Отображение доступных точек добавления

Для каждой панели приложение вычисляет список допустимых рёбер через `getEligibleEdges(panelId)`.

Для каждого допустимого ребра создаётся SVG-кнопка `+`:

- располагается по центру ребра;
- выносится наружу панели на визуальный отступ;
- скрыта по умолчанию на устройствах с мышью;
- появляется при наведении на группу панели;
- всегда видима на устройствах без hover;
- доступна по Tab;
- активируется кликом, Enter или Space;
- имеет `role="button"`;
- имеет динамический `aria-label`.

Пример:

`Add Right Panel to the right edge of Back Panel`.

## FR-007. Определение создаваемой физической грани

Новая грань определяется не по имени двумерного ребра, а по 3D-ориентации родительской панели.

После вычисления нового `basis.normal` вектор сопоставляется со справочником:

| Normal | faceKey | Имя |
|---|---|---|
| `[0, 0, 1]` | `front` | Front Panel |
| `[0, 0, -1]` | `back` | Back Panel |
| `[0, 1, 0]` | `top` | Top Panel |
| `[0, -1, 0]` | `bottom` | Base Panel |
| `[-1, 0, 0]` | `left` | Left Panel |
| `[1, 0, 0]` | `right` | Right Panel |

Если нормаль не соответствует одной из шести осей, добавление запрещается.

## FR-008. Запрет повторного использования грани

Перед отображением `+` и перед добавлением приложение проверяет наличие панели с рассчитанным `faceKey`.

Если панель уже существует:

- ребро не считается допустимым;
- `+` не отображается;
- `addPanel()` возвращает `null`.

Таким образом, модель никогда не содержит две панели `left`, две панели `bottom` и т. п.

## FR-009. Автоматический расчёт размеров панели

Размер панели определяется ориентацией её локальных осей:

- если локальная ось `right` направлена по мировой X, ширина панели равна `Width`;
- если по мировой Y, ширина равна `Height`;
- если по мировой Z, ширина равна `Depth`;
- аналогичное правило применяется к локальной оси `up` для высоты прямоугольника.

Функция `getAxisDimension(vector, dimensions)`:

- `abs(vector[0]) === 1` → `dimensions.width`;
- `abs(vector[1]) === 1` → `dimensions.height`;
- `abs(vector[2]) === 1` → `dimensions.depth`.

Это позволяет корректно отображать одну и ту же физическую грань как вертикальный или горизонтальный прямоугольник в зависимости от места присоединения.

## FR-010. Автоматическое позиционирование новой панели

Новая панель должна касаться родительской панели общей границей без зазора.

Формулы:

### Добавление сверху

```text
new.x = parent.x
new.y = parent.y - new.height
```

### Добавление справа

```text
new.x = parent.x + parent.width
new.y = parent.y
```

### Добавление снизу

```text
new.x = parent.x
new.y = parent.y + parent.height
```

### Добавление слева

```text
new.x = parent.x - new.width
new.y = parent.y
```

Размер общей границы автоматически совпадает благодаря 3D basis-модели.

## FR-011. Проверка пересечений

Перед добавлением создаётся потенциальный прямоугольник.

Он проверяется на пересечение со всеми существующими панелями.

Два прямоугольника считаются пересекающимися, если их внутренние области перекрываются по обеим осям.

Касание границ допустимо и не считается пересечением.

Используется epsilon `1e-7` для защиты от ошибок вычислений с плавающей точкой.

Если обнаружено пересечение:

- потенциальное добавление отвергается;
- кнопка `+` не отображается;
- состояние модели не изменяется.

## FR-012. Создание связи parent-child

При успешном добавлении:

1. создаётся объект дочерней панели;
2. `child.parentId` получает ID родителя;
3. `child.parentEdge` получает ребро родителя;
4. `parent.links[edge]` получает ID ребёнка;
5. `child.links[oppositeEdge]` получает ID родителя.

Пример:

```text
front.links.bottom = "bottom"
bottom.links.top = "front"
bottom.parentId = "front"
bottom.parentEdge = "bottom"
```

## FR-013. Удаление панели

Панель можно удалить, если:

- она существует;
- она не является root-панелью Front;
- у неё нет дочерних панелей.

Кнопка `−` не должна отображаться для:

- Front Panel;
- панели, имеющей хотя бы одного ребёнка.

При удалении:

1. в родительской панели очищается соответствующая ссылка;
2. панель удаляется из `Map`;
3. выполняется повторная отрисовка;
4. ранее недоступные `+` могут снова стать доступными;
5. `Continue` отключается, если число панелей стало меньше 6.

Удаление не является рекурсивным. Родитель с дочерними панелями нельзя удалить до удаления всех детей.

## FR-014. Счётчик размещённых панелей

Счётчик должен иметь формат:

`Placed panels: X/6`

где `X = model.panels.size`.

Допустимый диапазон X: от 1 до 6.

## FR-015. Состояние завершения

Модель считается завершённой только при:

```text
panelCount === 6
```

Поскольку дубликаты граней запрещены, шесть панелей означают наличие всех шести физических граней.

При завершении:

- `model.isComplete === true`;
- `Continue.disabled === false`;
- допустимые точки добавления отсутствуют.

## FR-016. Кнопка Continue

Кнопка `Continue`:

- отключена при 1–5 панелях;
- активна при 6 панелях;
- не выполняет действие, если модель не завершена;
- открывает итоговый диалог при завершённой модели.

## FR-017. Итоговый диалог

Диалог должен содержать:

- заголовок `Basic box created`;
- поясняющий текст;
- Width;
- Height;
- Depth;
- `Panels: 6 / 6`;
- кнопку `Back`;
- кнопку `Export SVG`.

При открытии:

- backdrop становится видимым;
- фокус перемещается на `Export SVG`;
- генерируется событие `box-net-complete`;
- в `event.detail` передаётся сериализованное состояние модели.

Диалог закрывается:

- кнопкой `Back`;
- кликом по backdrop вне содержимого;
- клавишей Escape.

После закрытия фокус возвращается на `Continue`.

## FR-018. Кнопка Cancel

Кнопка `Cancel` в текущем прототипе выполняет сброс развёртки, а не закрытие браузерного окна.

Если размещена только Front Panel:

- сброс выполняется сразу.

Если панелей больше одной:

- показывается confirm `Reset the current box layout?`;
- при отказе действие отменяется;
- при подтверждении модель сбрасывается.

После сброса:

- остаётся Front Panel;
- размеры сохраняются;
- показывается toast `The box layout was reset.`;
- генерируется событие `box-net-cancelled`.

## FR-019. Автоматическое масштабирование

Приложение не хранит фиксированный коэффициент px/mm.

После каждого изменения:

1. вычисляется bounding box всех панелей;
2. добавляется динамический отступ;
3. формируется SVG `viewBox`;
4. развёртка автоматически вписывается в рабочую область.

Это гарантирует, что схема остаётся полностью видимой при разных размерах и конфигурациях.

## FR-020. Реакция на изменение размера окна

`ResizeObserver` отслеживает контейнер `.workspace-wrap`. Если API недоступен,
приложение подписывается на событие `window.resize`.

При изменении размеров контейнера вызывается `render()`, после чего:

- пересчитывается viewBox;
- пересчитываются размеры линий, текста и кнопок в координатах модели;
- визуальные элементы сохраняют приблизительно постоянный пиксельный размер.

## FR-021. Экспорт SVG

Экспорт доступен из итогового диалога.

Экспортированный SVG:

- содержит только панели и подписи;
- не содержит кнопок `+` и `−`;
- использует миллиметры в атрибутах `width` и `height`;
- содержит `viewBox` с небольшим отступом;
- сохраняет цвет Front Panel;
- сохраняет цвет Base Panel;
- остальные панели белые;
- содержит чёрные контуры;
- содержит подписи только Front Panel и Base Panel;
- скачивается через временный Blob URL.

Имя файла:

```text
box-net-{Width}x{Height}x{Depth}mm.svg
```

Пример:

```text
box-net-150x90x40mm.svg
```

## FR-022. Форматирование чисел

Если значение целое, оно отображается без десятичной части.

Если дробное:

- округляется до двух знаков;
- незначащие нули удаляются преобразованием обратно в Number.

Примеры:

- `150` → `150`;
- `40.5` → `40.5`;
- `40.567` → `40.57`.

# 8. Подробная геометрическая модель

## 8.1. Две системы координат

Приложение одновременно использует:

### 3D-систему коробки

Оси:

- X — ширина коробки;
- Y — высота коробки;
- Z — глубина коробки.

### 2D-систему SVG-развёртки

- X увеличивается вправо;
- Y увеличивается вниз;
- каждая панель задаётся прямоугольником `x, y, width, height`.

3D-ориентация определяет физическую грань. 2D-координаты определяют её положение на экране.

## 8.2. Локальный basis панели

Каждая панель хранит:

```js
basis: {
  normal: [x, y, z],
  up: [x, y, z],
  right: [x, y, z]
}
```

Условия:

- каждый вектор направлен вдоль одной мировой оси;
- компоненты принимают значения `-1`, `0`, `1`;
- в каждом векторе ровно одна ненулевая компонента;
- векторы ортогональны;
- `normal` однозначно определяет физическую грань;
- `right` определяет горизонтальный размер прямоугольника;
- `up` определяет вертикальный размер прямоугольника.

## 8.3. Исходный basis Front Panel

```js
normal = [0, 0, 1]
up     = [0, 1, 0]
right  = [1, 0, 0]
```

Отсюда:

- ширина = размер по X = Width;
- высота = размер по Y = Height;
- физическая грань = Front.

## 8.4. Преобразование basis при сгибе

Пусть у родителя:

- `N = normal`;
- `U = up`;
- `R = right`.

### Через верхнее ребро

```text
child.normal = U
child.up     = -N
child.right  = R
```

### Через нижнее ребро

```text
child.normal = -U
child.up     = N
child.right  = R
```

### Через правое ребро

```text
child.normal = R
child.up     = U
child.right  = -N
```

### Через левое ребро

```text
child.normal = -R
child.up     = U
child.right  = N
```

Эти правила моделируют поворот грани коробки на 90 градусов вокруг выбранного ребра.

## 8.5. Пример вычисления Base Panel

Front:

```text
N = [0,0,1]
U = [0,1,0]
R = [1,0,0]
```

Добавление снизу:

```text
normal = -U = [0,-1,0] → bottom
up     = N  = [0,0,1]  → Depth
right  = R  = [1,0,0]  → Width
```

Результат:

```text
Base Panel = Width × Depth
```

## 8.6. Пример вычисления Left Panel

Добавление слева от Front:

```text
normal = -R = [-1,0,0] → left
up     = U  = [0,1,0]  → Height
right  = N  = [0,0,1]  → Depth
```

Результат:

```text
Left Panel = Depth × Height
```

## 8.7. Инварианты модели

В любой момент должны выполняться условия:

1. существует ровно одна Front Panel;
2. количество панелей от 1 до 6;
3. ID панели совпадает с `faceKey`;
4. каждый `faceKey` уникален;
5. rootId всегда `front`;
6. Front Panel не имеет parent;
7. каждая другая панель имеет существующего parent;
8. связь parent-child двусторонняя;
9. панели не перекрываются внутренними областями;
10. размеры панелей положительны;
11. размер панели соответствует её basis;
12. normal принадлежит множеству шести осевых направлений;
13. граф связей является деревом с корнем Front;
14. цикл связей невозможен, поскольку панель создаётся только один раз;
15. complete означает ровно шесть уникальных граней.

# 9. Структура данных

## 9.1. Объект модели

```js
class BoxNetModel {
  dimensions: {
    width: number,
    height: number,
    depth: number
  };
  panels: Map<string, Panel>;
  creationSequence: number;
  rootId: string;
}
```

## 9.2. Объект Panel

```js
{
  id: string,
  faceKey: "front" | "back" | "top" | "bottom" | "left" | "right",
  faceName: string,
  basis: {
    normal: [number, number, number],
    up: [number, number, number],
    right: [number, number, number]
  },
  x: number,
  y: number,
  width: number,
  height: number,
  parentId: string | null,
  parentEdge: "top" | "right" | "bottom" | "left" | null,
  order: number,
  links: {
    top: string | null,
    right: string | null,
    bottom: string | null,
    left: string | null
  }
}
```

## 9.3. Значение поля order

`order` фиксирует последовательность создания.

Отрисовка выполняется по возрастанию `order`, поэтому более поздние панели добавляются в SVG позже и визуально располагаются поверх более ранних элементов в случае совпадения границ.

Пересечения запрещены, поэтому реальное наложение площадей не возникает.

## 9.4. Сериализованное состояние

Метод `toJSON()` возвращает:

```json
{
  "dimensions": {
    "width": 150,
    "height": 90,
    "depth": 40
  },
  "complete": true,
  "panels": [
    {
      "id": "front",
      "name": "Front Panel",
      "x": 0,
      "y": 0,
      "width": 150,
      "height": 90,
      "parentId": null,
      "parentEdge": null,
      "basis": {
        "normal": [0, 0, 1],
        "up": [0, 1, 0],
        "right": [1, 0, 0]
      }
    }
  ]
}
```

Поле `links` и `order` в публичный JSON не включаются.

# 10. API модели

## 10.1. `new BoxNetModel(dimensions)`

Создаёт модель и вызывает `reset(dimensions)`.

### Вход

```js
{ width, height, depth }
```

### Ошибки

Выбрасывает Error при недопустимых размерах.

## 10.2. `reset(dimensions)`

- нормализует размеры;
- очищает Map;
- обнуляет creationSequence;
- создаёт Front Panel;
- устанавливает rootId;
- возвращает `this`.

## 10.3. `getPanel(panelId)`

Возвращает Panel или `null`.

## 10.4. `getPanels()`

Возвращает новый массив панелей, отсортированный по `order`.

## 10.5. `panelCount`

Getter. Возвращает размер Map.

## 10.6. `isComplete`

Getter. Возвращает `panelCount === 6`.

## 10.7. `getChildren(panelId)`

Возвращает все панели, у которых `parentId` равен переданному ID.

## 10.8. `canDelete(panelId)`

Возвращает false для root и для панелей с детьми.

## 10.9. `getPotential(panelId, edge)`

Выполняет полную проверку потенциального добавления.

Возвращает `null`, если:

- edge не входит в список EDGES;
- панель не существует;
- ребро занято;
- basis не соответствует физической грани;
- такая грань уже существует;
- прямоугольник пересекает существующую панель.

При успехе возвращает:

```js
{
  faceKey,
  faceName,
  basis,
  x,
  y,
  width,
  height
}
```

Метод не изменяет состояние.

## 10.10. `getEligibleEdges(panelId)`

Возвращает массив рёбер, для которых `getPotential()` не равен null.

Порядок проверки:

```text
top, right, bottom, left
```

## 10.11. `addPanel(panelId, edge)`

- повторно проверяет potential;
- создаёт панель;
- связывает parent и child;
- возвращает созданную панель.

При невозможности возвращает `null` без исключения.

## 10.12. `deletePanel(panelId)`

Возвращает:

- `true` при успешном удалении;
- `false`, если панель не существует или не может быть удалена.

## 10.13. `getBounds()`

Возвращает:

```js
{
  minX,
  minY,
  maxX,
  maxY,
  width,
  height
}
```

Для пустой модели предусмотрено защитное значение `0,0,1,1`, хотя штатно модель никогда не бывает пустой.

## 10.14. `toJSON()`

Возвращает независимое сериализуемое представление состояния.

# 14. Алгоритм рендеринга

## 14.1. Общий цикл

`render()` всегда строит SVG заново из состояния модели.

Порядок:

1. вызвать `getViewMetrics()`;
2. очистить SVG через `replaceChildren()`;
3. установить viewBox;
4. получить панели в порядке создания;
5. вызвать `renderPanel()` для каждой;
6. обновить счётчик;
7. обновить disabled у Continue;
8. обновить aria-label workspace.

Такой подход исключает рассинхронизацию DOM и модели.

## 14.2. Вычисление viewBox

1. Получить bounds.
2. `maxDimension = max(bounds.width, bounds.height)`.
3. `paddingFactor = min(0.3, 0.18 + panelCount × 0.02)`.
4. `padding = max(16, maxDimension × paddingFactor)`.
5. Расширить bounds на padding.
6. Сравнить размер viewBox с пиксельным размером SVG.
7. Вычислить scale.
8. Получить `unitPerPixel = 1 / scale`.

## 14.3. Стабилизация визуальных размеров

Поскольку viewBox изменяется, размеры UI-контролов переводятся из желаемых пикселей в единицы SVG:

- strokeWidth ≈ 1 px;
- fontSize ≈ 12 px;
- buttonRadius ≈ 7 px;
- buttonOffset ≈ 10 px;
- actionStroke ≈ 1.2 px;
- hitPadding ≈ 18 px.

Это обеспечивает визуально одинаковый размер кнопок при разных физических размерах коробки.

## 14.4. Порядок элементов панели

Внутри group:

1. panel-hitbox;
2. title;
3. panel-shape;
4. label, если Front/Base;
5. remove-action, если разрешено;
6. edge-action для каждого eligible edge.

```text
Any layout
  -> change dimensions
  -> Front only with new dimensions
```

# 16. Обработка ошибок и защитное поведение

## 16.1. Ошибки ввода

Обрабатываются через `try/catch` в `applyDimensionChange()`.

Пользователь не видит stack trace.

## 16.2. Недопустимые операции модели

`addPanel()` и `deletePanel()` не выбрасывают ошибку для обычных недопустимых действий.

Они возвращают:

- `null` для неуспешного добавления;
- `false` для неуспешного удаления.

Это удобно для UI и автоматизированных тестов.

## 16.3. Некорректный edge

`getPotential()` возвращает null.

Низкоуровневые геометрические функции могут выбрасывать Error, если их вызвать напрямую с неизвестным edge или некорректным вектором.

## 16.4. Защита от потери работы

При смене размеров и при Cancel используются confirm-диалоги, если пользователь уже добавил панели.

## 16.5. Ограничение огромных значений

Лимит 100000 защищает от:

- чрезмерных значений viewBox;
- ухудшения точности;
- случайного ввода;
- потенциально тяжёлой SVG-геометрии.

# 18. Экспортированный SVG

## 18.1. Физический размер

Корневой SVG получает:

```xml
width="{overallWidth}mm"
height="{overallHeight}mm"
```

Размер включает небольшой внешний padding.

## 18.2. Содержимое

Каждая панель экспортируется как:

```xml
<g>
  <title>...</title>
  <rect ... />
  <text ...>...</text>
</g>
```

Text создаётся только для Front и Base.

## 18.3. Линии

Текущая версия использует одинаковую сплошную чёрную линию для всех границ.

Общие границы соседних панелей могут быть визуально наложены двумя одинаковыми линиями, поскольку каждая панель экспортирует полный прямоугольник.

Линии не классифицируются как cut или crease.

## 18.4. XML escaping

Имена панелей фиксированы и безопасны. Если в будущем имена станут пользовательскими, перед вставкой в SVG потребуется XML escaping.

## 18.5. Необходимые улучшения для производственного экспорта

- дедупликация общей границы;
- разделение cut и crease;
- stroke colors по стандарту;
- компенсация толщины;
- допуски;
- единый path;
- metadata;
- профиль единиц;
- проверка в профессиональных редакторах.

# 22. Нефункциональные требования

## NFR-001. Автономность

Приложение должно работать без сети после получения HTML-файла.

## NFR-002. Конфиденциальность

Данные не отправляются на сервер. Размеры и схема существуют только в памяти страницы.

## NFR-003. Производительность

Максимум шесть панелей. Все вычисления имеют фактически постоянную сложность.

Ожидаемая реакция на действие — визуально мгновенная.

## NFR-004. Детерминированность

При одинаковых размерах и одинаковой последовательности действий результат должен быть идентичным.

## NFR-005. Точность

Геометрия хранится в числовых единицах, эквивалентных миллиметрам модели.

Пиксельный масштаб не влияет на геометрические размеры.

## NFR-006. Поддерживаемость

Бизнес-логика геометрии отделена от DOM-рендеринга.

## NFR-007. Тестируемость

Модель доступна как ES-модуль и тестируется через Vitest в Node без браузера.

## NFR-008. Безопасность

Приложение не выполняет пользовательский JavaScript и не загружает внешние ресурсы.

Текущие фиксированные строки безопасны для inner markup. Пользовательские размеры преобразуются в Number.

## NFR-009. Масштабируемость архитектуры

Текущая basis-модель может стать основой для:

- 3D-preview;
- mapping artwork между 2D и 3D;
- определения сгибов;
- сохранения orientation каждой панели.

# 25. Известные ограничения и технический долг

## 25.1. Cancel фактически означает Reset

Название может вводить в заблуждение. В host-приложении Cancel обычно должен закрывать wizard или возвращать на предыдущий шаг.

## 25.2. Нет сохранения

Обновление страницы полностью теряет состояние.

## 25.3. Нет undo/redo

Пользователь должен вручную удалять leaf-панели в обратном порядке.

## 25.4. Удаление только leaf

Это защищает дерево, но может быть неудобно. Возможная future-функция — удаление ветки с подтверждением.

## 25.5. Нет визуальных имён обычных панелей

Пользователь видит подписи только Front и Base.

## 25.6. Нет визуального различия cut/fold

Все линии одинаковы.

## 25.7. Нет ручного управления viewport

Только автоматический fit.

## 25.8. Browser confirm

Системные confirm нельзя стилизовать и локализовать на уровне приложения так же гибко, как собственный dialog.

## 25.9. Нет локализации

Все строки на английском и встроены в код.

## 25.10. SVG export не production dieline

Экспорт пригоден как геометрический прототип, но не как утверждённая производственная высечка.

## 25.11. Отсутствует импорт состояния

`toJSON()` есть, обратного `fromJSON()` нет.

## 25.12. Нет контроля дублированных линий

Смежные панели экспортируют общую линию дважды.

```text
front.left   -> left
```

| ID | x | y | width | height | parent | parentEdge |
|---|---:|---:|---:|---:|---|---|
| front | 0 | 0 | 150 | 90 | null | null |
| bottom | 0 | 90 | 150 | 40 | front | bottom |
| top | 0 | -40 | 150 | 40 | front | top |
| back | 0 | -130 | 150 | 90 | top | top |
| left | -40 | 0 | 40 | 90 | front | left |
| right | 150 | -130 | 40 | 90 | back | right |

```text
minX = -40
minY = -130
maxX = 190
maxY = 130
width = 230
height = 260
```

Физические грани:

```text
front, bottom, top, back, left, right
```

`complete = true`.

# 29. Краткая памятка разработчику

Главная архитектурная идея приложения состоит в следующем:

> Не пытаться угадывать тип новой панели по её двумерному положению. Каждая панель должна хранить 3D basis. При переходе через ребро basis поворачивается на 90°, normal определяет физическую грань, а up/right определяют размеры её 2D-прямоугольника.

Именно это обеспечивает:

- корректные размеры;
- корректный поворот;
- уникальность шести граней;
- возможность присоединить боковую грань к разным панелям основной ленты;
- предсказуемый экспорт;
- расширяемость в сторону 3D.

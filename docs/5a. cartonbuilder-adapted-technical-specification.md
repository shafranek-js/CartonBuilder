# CartonBuilder — адаптированная техническая спецификация

Статус: проектный контракт для следующего этапа разработки<br>
Версия: 1.0<br>
Дата: 2026-07-30

## 1. Назначение и приоритет документов

Этот документ адаптирует `5. carton_developer_technical_specification.html`
под существующее приложение CartonBuilder. Он не заменяет реализованный
контракт 2D-редактора, а дополняет его требованиями к 3D-preview.

При расхождении документов действует следующий приоритет:

1. `3. artwork-placement-runtime-specification.md` — текущее поведение
   реализованной 2D-версии.
2. Этот документ — архитектура и критерии следующего 3D-инкремента.
3. `3. artwork-placement-answers-2026-07-30.md` — продуктовые решения и
   исходные ответы.
4. `4. Browser-Based 3D for a Box-Net and Artwork App.pdf` и исходная
   HTML-спецификация — исследовательские рекомендации.

Исходные compatibility-контракты, схема `BoxNetModel.toJSON()`, имена граней,
геометрия развёртки и существующие форматы экспорта не меняются.

## 2. Текущее состояние проекта

CartonBuilder уже является Vite-приложением на Vanilla JavaScript и
ES-модулях. Переход на React, Vue, TypeScript или отдельный state framework для
добавления 3D не требуется.

### 2.1. Реализованный baseline

- построение валидной развёртки из шести прямоугольных граней;
- геометрия и artwork transform в миллиметрах;
- импорт одного PNG, JPEG или выбранной страницы PDF;
- проверка MIME, сигнатуры, размера и повреждённых файлов;
- локальный PDF preview и сохранение исходной PDF-страницы для экспорта;
- move, proportional resize, quarter-turn rotation, opacity и numeric inputs;
- независимые artwork и viewport transforms;
- undo/redo с лимитом 100 завершённых команд;
- SVG-редактор, union clipping и различение cut/fold lines;
- Preview / Export с PNG, JPG, SVG и PDF;
- PDF 1:1, `Dieline` OCG и `/Separation /CutContour`;
- IndexedDB autosave и ZIP-контейнер `.carton`;
- EN/RU, keyboard interaction, live announcements и диагностика;
- Vitest и Playwright;
- GitHub Pages deployment.

### 2.2. Следующий инкремент

Следующий инкремент добавляет 3D folded preview, производный от существующих
`BoxNetModel` и `ArtworkModel`. Он не расширяет scope до клапанов,
непрямоугольных панелей, нескольких artwork-слоёв или prepress-проверок.

## 3. Продуктовый workflow

В приложении сохраняются три шага:

1. **Create Box** — построение развёртки 6/6.
2. **Place Artwork** — загрузка и размещение единого artwork.
3. **Preview / Export** — 2D proof, 3D folded preview и экспорт.

3D не добавляется отдельным четвёртым шагом. Внутри третьего шага появляются
переключаемые представления:

- **2D Preview**;
- **3D Preview**.

Панель экспорта остаётся доступной независимо от выбранного представления.
Отсутствие WebGL не должно блокировать 2D-preview, сохранение проекта или
экспорт.

## 4. Неприкосновенные инварианты

### 4.1. Источник истины

- `BoxNetModel` — единственный источник геометрии граней и связей.
- `ArtworkModel` — единственный источник положения, масштаба, поворота и
  прозрачности artwork.
- `ViewportModel` управляет только 2D-камерой и не влияет на геометрию.
- Three.js scene, meshes, textures, pivots и camera являются временными
  render-ресурсами.
- Экспорт никогда не читает геометрию из Three.js scene или WebGL framebuffer.

### 4.2. Единицы и координаты

- Каноническая единица — миллиметр.
- Глобальный 2D origin находится в левом верхнем углу Front Panel.
- В 2D X направлен вправо, Y — вниз.
- Экранные пиксели применяются только в `ViewportModel` и pointer mapping.
- PDF использует `72 / 25.4` points на миллиметр.
- 3D использует одну world unit на миллиметр. Дополнительный масштаб модели
  допустим только как transform корневого preview-контейнера.

### 4.3. Совместимость

Без изменений сохраняются:

- `window.BoxNet`;
- `window.boxNetApp`;
- `window.cartonBuilderApp`;
- события `box-net-complete` и `box-net-cancelled`;
- `BoxNetModel.toJSON()` и `BoxNetModel.fromJSON()`;
- имена `front`, `back`, `left`, `right`, `top`, `bottom`;
- Front Panel как корень;
- Base Panel как физическая грань `bottom`;
- лимиты размеров, значения по умолчанию и SVG filename;
- импорт и экспорт существующих `.carton` version 1.

Допускается только аддитивный интерфейс
`window.cartonBuilderApp.preview3d`. Его отсутствие не должно нарушать
существующие интеграции.

## 5. Канонические модели

### 5.1. BoxNetModel

3D-слой использует существующий сериализованный panel contract:

```js
{
  id,             // physical face id
  name,
  x, y,           // flat-net millimetres
  width, height,  // millimetres
  parentId,
  parentEdge,     // top | right | bottom | left
  basis: {
    normal: [x, y, z],
    up: [x, y, z],
    right: [x, y, z],
  },
}
```

`parentId` и `parentEdge` образуют дерево шарниров. `basis` задаёт ожидаемую
ориентацию физической грани в закрытой коробке. 3D-слой не должен выводить
иерархию из экранного положения панели и не должен предполагать фиксированную
крестообразную развёртку.

### 5.2. ArtworkModel

3D-слой читает существующие поля:

```js
{
  source,
  centerXmm,
  centerYmm,
  initialWidthMm,
  initialHeightMm,
  scale,
  rotation, // 0 | 90 | 180 | 270
  opacity,
}
```

Фактические размеры без поворота:

```text
widthMm  = initialWidthMm  × scale
heightMm = initialHeightMm × scale
```

Artwork остаётся единым непрерывным слоем. Отдельные transform или ориентация
на каждой панели запрещены.

### 5.3. 3D UI state

Для первого 3D-инкремента достаточно несериализованного состояния:

```js
{
  active: false,
  foldProgress: 1,
  selectedPanelId: null,
  cameraPreset: "isometric",
}
```

`foldProgress` находится в диапазоне `[0, 1]`, где `0` — плоская развёртка,
`1` — собранная коробка. Camera position и OrbitControls target не входят в
project schema version 1.

## 7. 3D geometry и hinge graph

### 7.1. Панели

- Каждая из шести панелей представлена отдельным `BufferGeometry`.
- Геометрия панели плоская и не деформируется при складывании.
- Локальные размеры mesh точно равны `panel.width × panel.height`.
- Front Panel является корнем сцены.
- Для каждой дочерней панели создаётся `Object3D` pivot на общей линии сгиба.
- Mesh смещается относительно pivot так, чтобы соответствующая дочерняя грань
  совпадала с шарниром.
- Дочерние pivots вложены рекурсивно, поэтому поворот родителя переносит всё
  его поддерево.

### 7.2. Направление складывания

Знак и ось target rotation выводятся из:

- `parentEdge`;
- basis родителя;
- basis ребёнка;
- результата тех же правил, которые использует `getAdjacentBasis()`.

Запрещено задавать знаки поворота таблицей, зависящей только от `panel.id` или
от конкретного reference net. Для любого допустимого дерева при
`foldProgress = 1` world normal каждой панели должен совпасть с
`panel.basis.normal`.

Текущий угол:

```text
angle = targetHingeAngle × foldProgress
```

Для прямоугольной коробки каждый отдельный hinge target равен `+90°` или
`-90°`. Плавность UI-анимации может задаваться easing-функцией, но
математические тесты работают с линейным `foldProgress`.

### 7.3. Ограничения

- Толщина картона не моделируется.
- Коллизии панелей не рассчитываются.
- Клапаны, glue tabs и непрямоугольные polygons отсутствуют.
- 3D не изменяет дерево панелей и не исправляет ошибочную 2D-геометрию.

## 8. Artwork texture и UV

### 8.1. Выбранная стратегия

Для первого инкремента применяется одна общая `CanvasTexture` в координатах
полной развёртки:

1. Canvas соответствует `boxModel.getBounds()`.
2. Исходный preview Blob рисуется с transform из `ArtworkModel`.
3. Quarter-turn rotation выполняется вокруг `centerXmm/centerYmm`.
4. Opacity берётся из `ArtworkModel`.
5. Область вне union шести панелей остаётся прозрачной.
6. Все шесть meshes используют одну texture.

Это derived preview asset. Он не сохраняется в project state и не используется
для PDF/PNG production export.

### 8.2. UV панелей

UV каждого угла вычисляется из его flat-net coordinate относительно общего
dieline bounds:

```text
u = (netX - bounds.minX) / bounds.width
v = 1 - (netY - bounds.minY) / bounds.height
```

Порядок UV должен учитывать локальную ориентацию mesh, но не изменять
ArtworkModel. На общей линии сгиба две панели должны читать один и тот же
texel с допустимой погрешностью фильтрации.

### 8.3. Texture policy

- используется preview, а не original PDF/raster Blob;
- максимальный edge — 4096 px;
- максимальная площадь — 16 миллионов пикселей;
- renderer pixel ratio ограничен `min(devicePixelRatio, 2)`;
- `ClampToEdgeWrapping`; повтор artwork запрещён;
- color space задаётся явно согласно актуальному Three.js API;
- texture обновляется после завершённой artwork-команды, а не на каждом
  промежуточном `pointermove`, если это вызывает заметные задержки;
- при замене artwork старая texture освобождается через `dispose()`.

## 9. 3D UI и взаимодействие

Обязательные controls:

- переключатель `2D Preview / 3D Preview`;
- slider `Open ↔ Folded`;
- кнопки `Open`, `Fold` и `Reset View`;
- OrbitControls: rotate, pan и zoom;
- выбор панели кликом через Raycaster;
- текстовый inspector выбранной панели: имя и размеры;
- DOM status summary для screen reader;
- сообщение о недоступности WebGL с возвратом к 2D Preview.

Поведение:

- при первом открытии показывается собранная коробка (`foldProgress = 1`);
- переключение между 2D и 3D не меняет artwork, viewport или history;
- изменение artwork в шаге 2 пересобирает texture при возврате в 3D;
- выбор панели использует тот же `panel.id`, что и 2D model;
- точное позиционирование artwork в 3D запрещено;
- keyboard focus не переносится в WebGL canvas без явного действия пользователя;
- `Escape` снимает выбор панели;
- `Reset View` восстанавливает детерминированную изометрическую камеру.

## 10. Render loop и lifecycle

- В приложении существует не более одного WebGL renderer.
- Scene создаётся лениво и переиспользуется между переключениями preview.
- Непрерывный `requestAnimationFrame` разрешён только во время fold animation,
  активного OrbitControls damping или другого визуального изменения.
- В статическом состоянии используется render-on-demand.
- Resize обрабатывается через `ResizeObserver` с существующим
  `window.resize` fallback.
- При изменении container size обновляются renderer size, camera aspect и
  projection matrix; модель и fold state не меняются.
- При закрытии/замене проекта освобождаются geometry, material, texture,
  ImageBitmap и renderer resources.
- `webglcontextlost` показывает recoverable status и не очищает canonical
  project state.

## 11. Import, persistence и export

Текущие pipelines остаются без изменений.

### 11.1. Import

- PNG/JPEG/PDF, максимум 100 MiB.
- PDF.js worker используется для PDF.
- PDF page picker обязателен при `pageCount > 1`.
- Preview ограничен 4096 px и 16 MP.
- Original Blob сохраняется отдельно от preview.
- Весь import выполняется локально и может быть отменён.

3D не создаёт второй import pipeline и не декодирует original Blob повторно,
если подходящий preview уже доступен.

### 11.2. Persistence

IndexedDB `carton-builder`, store `projects`, key `current` остаются текущим
autosave-контрактом. `.carton` version 1 остаётся совместимым.

Camera и fold progress не сохраняются на первом этапе. Если позднее потребуется
их persistence, они добавляются как optional view fields и не становятся
production geometry.

### 11.3. Export

3D-preview не изменяет:

- PNG/JPG 300 DPI и raster safety limits;
- SVG dieline contract;
- PDF physical page size;
- vector embedding исходной PDF page;
- `Dieline` Optional Content Group;
- `CutContour` spot separation;
- cut/fold styles.

Экспорт изображения 3D-сцены не входит в первый 3D-инкремент.

## 12. Accessibility

- Все команды представлены настоящими DOM `button`, `input` или `select`.
- WebGL canvas имеет понятное accessible name, но не притворяется полноценной
  семантической сценой.
- Выбранная панель и fold percentage дублируются текстом.
- Slider поддерживает стандартные Arrow, Home и End.
- Focus indicator соответствует существующему UI.
- Управление камерой имеет документированную keyboard/mouse alternative.
- `prefers-reduced-motion` отключает автоматическую fold animation; slider
  остаётся доступным.
- Ошибка и восстановление WebGL объявляются через polite live region.
- Основной экспорт доступен даже при отсутствии WebGL.

## 13. Performance, privacy и browser support

Целевая среда первого 3D-релиза:

- последняя стабильная версия desktop Chrome;
- viewport примерно от 1024 × 720;
- high-DPI и 4K displays;
- touch не является обязательным;
- WebGL2 предпочтителен, WebGL fallback допустим через Three.js;
- WebGPU не используется как единственный renderer.

Файлы не отправляются на сервер. Remote URL import отсутствует. Диагностика не
включает artwork bytes, filename, checksum или персональные идентификаторы.

Для одной коробки допустимы шесть отдельных meshes. Instancing не требуется.
Приоритет — корректный lifecycle и предсказуемая память, а не преждевременная
оптимизация draw calls.

## 15. Тестовая стратегия

### 15.1. Unit tests

Обязательны:

- hinge tree строится из `parentId`/`parentEdge`, а не из panel coordinates;
- все шесть panel IDs представлены ровно один раз;
- flat pose сохраняет исходную смежность;
- при `t = 1` normal/right/up каждой панели совпадают с basis;
- `t = 0`, `0.5`, `1` дают детерминированные transforms;
- соседние panel edges остаются совпадающими на всех значениях `t`;
- UV каждого panel corner соответствует flat-net coordinate;
- UV непрерывны вдоль общей fold line;
- quarter-turn artwork rotation корректно попадает в texture;
- texture dimensions соблюдают 4096 px / 16 MP policy;
- сериализованные box/artwork snapshots не меняются после 3D render.

### 15.2. Playwright

Обязательные сценарии:

- завершить 6/6, загрузить artwork, открыть 3D Preview;
- initial folded view содержит шесть панелей;
- Open, Fold и slider меняют только 3D state;
- OrbitControls и Reset View работают;
- выбор панели обновляет inspector и `selectedPanelId`;
- возврат в Artwork, move/rotate/opacity, затем 3D показывает обновлённый
  artwork;
- переключение 2D/3D сохраняет model и export outputs;
- resize не сбрасывает fold state;
- keyboard slider и Escape работают;
- имитация отсутствующего WebGL оставляет 2D/export доступными;
- существующие e2e-тесты проходят без изменений.

### 15.3. Visual regression

Фиксируются эталоны:

- полностью открытая развёртка;
- half-folded `t = 0.5`;
- закрытая коробка;
- artwork, пересекающий минимум две fold lines;
- artwork с rotation 90°;
- Front/Base/Back orientation с читаемым асимметричным fixture;
- desktop и high-DPI viewport.

Для стабильных screenshots отключаются damping, transition animation,
случайность, внешние ресурсы и недетерминированные тени.

## 16. Acceptance criteria

3D-инкремент считается завершённым, если:

1. 3D строится для любой развёртки, допустимой текущим `BoxNetModel`, а не
   только для одной контрольной раскладки.
2. Все панели при `foldProgress = 1` имеют ориентацию, заданную их basis.
3. Artwork непрерывно переходит через общие линии сгиба.
4. Изменение fold progress не меняет BoxNetModel или ArtworkModel.
5. Изменение artwork не требует пересоздания проекта и корректно появляется в
   3D.
6. 2D Preview и все существующие exports побитово или семантически сохраняют
   прежние контракты.
7. При отсутствии WebGL пользователь может продолжить 2D workflow и экспорт.
8. Повторное открытие 3D и 20 замен artwork не приводят к накоплению активных
   textures, materials или animation loops.
9. Основные команды 3D доступны с клавиатуры и имеют текстовый статус.
10. `npm run test:all` и `npm run build` завершаются успешно.

## 17. Зафиксированные решения

| Область | Решение для CartonBuilder |
|---|---|
| UI stack | Vite + Vanilla JavaScript + ES modules |
| 3D engine | Three.js, lazy-loaded |
| Source of truth | Существующие 2D `BoxNetModel` и `ArtworkModel` |
| Box topology | Только шесть прямоугольных физических граней |
| Flaps / glue tabs | Не поддерживаются |
| Artwork layers | Один artwork asset |
| Artwork rotation | Только 0°, 90°, 180°, 270° |
| Initial artwork fit | Fit + Center по bounds всей развёртки |
| PDF pages | Обязательный selector для multipage PDF |
| 3D placement editing | Не поддерживается |
| 3D location in workflow | Внутри шага Preview / Export |
| Initial 3D pose | Folded, `foldProgress = 1` |
| Texture strategy | Одна derived net-space CanvasTexture |
| File processing | Локально в браузере |
| Maximum original asset | 100 MiB |
| Preview cap | 4096 px edge, 16 MP |
| Bleed / safe area / marks | Не поддерживаются |
| PDF/X / overprint | Вне текущего scope |
| Target browser | Desktop Chrome, примерно от 1024×720 |
| Touch | Не является обязательным |
| 3D image export | Вне первого 3D-инкремента |

## 18. Не входит в scope

- изменение существующей 2D-геометрии ради упрощения 3D;
- отдельный 3D project model;
- редактирование artwork на поверхности коробки;
- thickness, bevels, flaps, glue tabs и физическая симуляция;
- несколько artwork-слоёв;
- автоматическое распознавание dieline в PDF;
- проверка соответствия размеров входного PDF коробке;
- server upload, collaboration и approval workflow;
- PDF/X, trapping, overprint и полный production prepress;
- WebGPU-only renderer;
- сохранение camera position в `.carton` version 1.
